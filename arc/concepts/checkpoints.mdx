A checkpoint identifies the routing model configuration behind an ARC decision. Keep track of the resolved checkpoint when comparing behavior over time.

In the development platform, a workspace can choose **Latest** or **Pinned**. Latest uses the current alias; pinned keeps the workspace on the configured checkpoint. Only workspace owners can change this setting.

ARC is in private preview. Confirm the checkpoints available to your workspace and any upgrade requirements with the Rayline team before changing your integration.

## Before changing a checkpoint

Compare task completion, quality, latency, and total cost on representative tasks. Keep the same input set and record the checkpoint for each run. Do not interpret a different selected model as an improvement by itself.

## What is not yet a contract

The current preview does not let a request override the workspace checkpoint by supplying a model field. Release cadence, deprecation windows, rollback policy, and production model-ID mappings will be documented with the live service.
