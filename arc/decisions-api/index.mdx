With the Decisions API, you send a state, such as a conversation, a document or a JSON record, and up to 16 typed questions about it. ARC answers each question with a probability, a choice or a score in one request, and generates no text.

Use it for cheap, structured judgements inside your application: whether a customer's issue is resolved, which queue a ticket belongs in, how urgent it is, or which model should handle a request. You pay only for the input tokens ARC reads, and every question about one state shares one read of it.

```bash
curl --fail-with-body https://api.rayline.ai/v1/decisions \
  -H "Authorization: Bearer $RAYLINE_API_KEY" \
  -H "Content-Type: application/json" \
  -d @- <<'JSON'
{
  "model": "arc-1.0",
  "state": {
    "messages": [
      {"role": "user", "content": "My March invoice charged me twice for the Pro plan."},
      {"role": "assistant", "content": "Sorry about that. I've refunded the duplicate charge; it will show on your card in 3-5 business days."},
      {"role": "user", "content": "Got it, thanks for sorting that out so fast!"}
    ]
  },
  "questions": {
    "resolved": {"type": "noul", "instructions": "Has the customer's issue been resolved?"}
  }
}
JSON
```

```json
{
  "model": "arc-1.0",
  "answers": {"resolved": {"type": "noul", "noul": 0.81}},
  "usage": {"input_tokens": 99, "output_tokens": 0}
}
```

## Question types

| Type | You send | ARC answers |
| --- | --- | --- |
| `noul` | A yes-or-no question in `instructions` | `noul`: the probability, from 0 to 1, that the answer is true |
| `choice` | `instructions` and the options in `criteria` | `choice`: the most likely option, with `confidence` and the `probabilities` of every option |
| `score` | `instructions` and an ordered scale, low to high, in `criteria` | `score`: the expected level on the scale, with `confidence`, the `probabilities` of every level, and a `legend` |

Questions are free-form: write each one in plain language in `instructions`. The request carries only `model`, `state` and `questions`, in the same shape as TypeSafe's Jev API. Image questions (`box`) are not supported.

See [question types](/arc/decisions-api/question-types) for each type's fields and answers.

## Model IDs

Send the ARC model ID for your data mode in `model`. The Decisions API uses the same IDs as [ARC Dynamic](/arc/dynamic).

| Model ID | Data mode |
| --- | --- |
| <code>{decisionsModel}</code> | Standard |
| <code>{decisionsContributorModel}</code> | Contributor |
| <code>{decisionsZdrModel}</code> | Zero data retention |

An organization on zero data retention must use <code>{decisionsZdrModel}</code>; other IDs return `403` (`zdr_model_required`). See [pricing and privacy](/arc/decisions-api/pricing-and-privacy).

## How it differs from the Routes API

The Routes API and the Decisions API both read your input and generate nothing. They answer different questions.

| | Routes API | Decisions API |
| --- | --- | --- |
| Endpoint | `POST /v1/routes` | `POST /v1/decisions` |
| What it answers | Which model and reasoning configuration should run this turn | Your own questions about a state |
| Input | The body you would send to generate the turn (Anthropic Messages, Chat Completions or Responses) | A `state` of any JSON, and a `questions` map |
| Output | A route: `model`, `thinking`, presets and alternatives | One answer per question: a probability, choice or score |
| Model IDs | `arc-swift-1.0`, `arc-sage-1.0`, `arc-1.0` and their data-mode IDs | <code>{decisionsModel}</code> and its data-mode IDs |
| Error body | Anthropic format, `{"type": "error", "error": {...}}` | `{"error": "<code>", "detail": {...}}`, with two exceptions listed in [errors](/arc/decisions-api/limits-and-errors#errors) |
| Billing | Input tokens ARC reads, no output charge | The same rates as the Routes API: input tokens ARC reads, including your questions, no output charge |

A body without a top-level `questions` member is a route lookup: `/v1/decisions` refuses it with `400` (`use_routes_endpoint`). Send it to [`POST /v1/routes`](/arc/routes) instead.

## Billing

The Decisions API is priced the same as the Routes API, in each data mode: Standard, Contributor and zero data retention. A request is billed for the input tokens ARC reads: your state plus every question you ask, as reported in `usage.input_tokens`. There is no output charge. Refused requests are not billed. The model ID you send sets the data mode and its rate. See [pricing and privacy](/arc/decisions-api/pricing-and-privacy) and current rates on [rayline.ai/pricing](https://rayline.ai/pricing).

## Data use

ARC reads your state and questions to answer the request and keeps neither once it has answered. Usage records carry token counts and metadata, not your state or questions. See [pricing and privacy](/arc/decisions-api/pricing-and-privacy#what-is-kept).
