## Limits

| Limit | Value |
| --- | --- |
| Questions per request | 16 |
| State plus the longest question | 32,768 tokens, counted by ARC's tokenizer; `422` (`state_too_long`) reports the count |
| One question | 8,192 tokens |
| `choice` options | 1 to 64 |
| `score` levels | 1 to 10 |
| Rate | 30 requests per minute per user, counted separately from the Routes API |

ARC answers all of a request's questions in one read of the state, so adding questions costs their own tokens, not another read of the state.

## Retries

| Status | What to do |
| --- | --- |
| `429` `rate_limited` | Wait the seconds in the `Retry-After` header, then retry |
| `429` `capacity` | Wait the `Retry-After` header when it is sent; otherwise retry with backoff |
| `503` `question_head_unavailable` | Retry. While ARC is starting up after a quiet period, the response carries `Retry-After: 30`; otherwise back off |
| Any other error | Don't retry; fix the request |

```python
import time
import requests

def decide(body, key, attempts=5):
    for _ in range(attempts):
        r = requests.post(
            "https://api.rayline.ai/v1/systemone",
            headers={"Authorization": f"Bearer {key}"},
            json=body,
            timeout=30,
        )
        if r.status_code not in (429, 503):
            r.raise_for_status()
            return r.json()
        time.sleep(int(r.headers.get("Retry-After", "5")))
    r.raise_for_status()
```

## Errors

Errors use the same bodies as TypeSafe's API. The error code is in the `x-rayline-error-code` response header on every refusal, so branch on that header rather than on the message text.

Most refusals carry a message:

```json
{"detail": "Too many requests. Retry after 33 seconds."}
```

A `422` carries a list of validation errors, each with the location of the problem (`loc`), a message (`msg`) and the error code (`type`):

```json
{"detail": [{"loc": ["body", "state"], "msg": "state is 65429 tokens; at most 32768 are read", "type": "state_too_long"}]}
```

| Status | Code | When |
| --- | --- | --- |
| `400` | `invalid_body` | The body has no `state`, has a member other than `model`, `state` and `questions`, or a `state` message has no string `role` (`"Invalid request body: state."`). On `/v1/systemone`, also a body with no `questions`. |
| `400` | `use_routes_endpoint` | `/v1/decisions` only: the body has no `questions`, so it is a route lookup. Send it to [`POST /v1/routes`](/arc/reference/routes). This one refusal uses the Anthropic format, `{"type": "error", "error": {...}}`, and is answered before your key is checked. |
| `401` | `authentication_error` | The API key is missing (`"Missing authentication."`) or invalid (`"Invalid credentials."`) |
| `402` | `billing_error` | The workspace has no balance to pay for the request. The message links to the top-up page; see [add funds](/platform/billing#which-balance-pays). |
| `403` | `zdr_model_required` | Your organization uses zero data retention and `model` is not <code>{decisionsZdrModel}</code>. The message names the ID to use. |
| `403` | `contributor_models_off` | `model` is <code>{decisionsContributorModel}</code> and **Allow Contributor models** is off for the organization |
| `403` | `model_not_allowed` | Your organization's data mode does not allow this request right now. Your state was not sent. |
| `404` | `model_not_found` | `model` is not one of the three Decisions model IDs. ARC model IDs for generation and the Routes API, such as `arc-1.0`, `arc-swift-1.0` and `arc-sage-1.0` and their data-mode IDs, are refused too. The message names <code>{decisionsModel}</code>. |
| `404` | `decisions_not_available` | The Decisions API is not enabled on this host |
| `422` | `missing` | `model` is missing (`loc` `["body", "model"]`, `msg` `Field required`). There is no default model. |
| `422` | `string_type` | `model` is not a string (`loc` `["body", "model"]`) |
| `422` | `invalid_question` | More than 16 questions (`loc` `["body", "questions"]`, `msg` `at most 16 questions per request`); `questions` is empty or not an object; or a question has an unknown `type` or member, malformed or out-of-range `criteria`, or more than 8,192 tokens. `loc` names the question when there is one, such as `["body", "questions", "urgency"]`. |
| `422` | `question_type_not_supported` | A `box` question, or `assets` in a question or at the top level of the body. `loc` names the question when there is one. |
| `422` | `state_too_long` | The state plus its longest question is over 32,768 tokens. `msg` gives the count. Shorten the state. |
| `429` | `rate_limited` | Rate limit reached. `Retry-After` gives the wait in seconds. |
| `429` | `capacity` | ARC is at capacity. `Retry-After` gives the wait when it is sent. |
| `503` | `question_head_unavailable` | Temporarily unavailable, or starting up after a quiet period (with `Retry-After: 30`) |

A body that is not valid JSON is refused with `400` before any of these checks, and that response has no JSON body.

Refused requests are not billed. A request refused with `invalid_body`, `invalid_question`, `question_type_not_supported`, `state_too_long`, `capacity` or `question_head_unavailable` can still count toward the rate limit.

See [errors and limits](/arc/reference/errors) for troubleshooting that applies to every Rayline API.
