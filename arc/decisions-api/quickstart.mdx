<Steps>
<Step title="Get a key and add funds">
Create a key in **API Keys** on the [Rayline Platform](https://platform.rayline.ai/keys) and add funds to the workspace; see [API keys](/platform/api-keys) and [funding and billing](/platform/billing). Without a balance, requests return `402` (`billing_error`). Keep the key in `RAYLINE_API_KEY`, outside your source code:

```bash
export RAYLINE_API_KEY="<your Rayline API key>"
```
</Step>
<Step title="Ask a question">

Send a `state` and a map of `questions`. Each question has an ID you choose, which keys its answer in the response. This request triages a support ticket with one question of each type:

```bash
curl --fail-with-body https://api.rayline.ai/v1/decisions \
  -H "Authorization: Bearer $RAYLINE_API_KEY" \
  -H "Content-Type: application/json" \
  -d @- <<'JSON'
{
  "model": "arc-1.0",
  "state": "Subject: Checkout broken\n\nHi, since this morning our checkout page shows a blank screen after customers click Pay. We've lost about 40 orders already. Tried Chrome and Safari. You can reach me at dana.reyes@example.com or +1 415 555 0134.",
  "questions": {
    "is_bug": {"type": "noul", "instructions": "Is the customer reporting a bug?"},
    "team": {
      "type": "choice",
      "instructions": "Which team should own this ticket?",
      "criteria": {
        "payments": "Checkout, payment and billing problems",
        "accounts": "Sign-in and user accounts",
        "docs": "Documentation questions"
      }
    },
    "urgency": {
      "type": "score",
      "instructions": "How urgent is this ticket?",
      "criteria": ["Can wait", "Needs attention this week", "Needs attention today", "Blocking revenue right now"]
    }
  }
}
JSON
```
</Step>
<Step title="Read the answers">

```json
{
  "model": "arc-1.0",
  "answers": {
    "is_bug": {"type": "noul", "noul": 0.6},
    "team": {
      "type": "choice",
      "choice": "payments",
      "confidence": 0.81,
      "probabilities": {"payments": 0.87, "accounts": 0.07, "docs": 0.06}
    },
    "urgency": {
      "type": "score",
      "score": 1.91,
      "confidence": 0.26,
      "legend": {"0": "Can wait", "1": "Needs attention this week", "2": "Needs attention today", "3": "Blocking revenue right now"},
      "probabilities": {"0": 0.11, "1": 0.2, "2": 0.36, "3": 0.33}
    }
  },
  "usage": {"input_tokens": 218, "output_tokens": 0}
}
```

Probabilities are rounded to two decimals. `noul` is the probability that the answer is true. `choice` is the most likely option. `score` is the expected level, counting levels from `0`; `legend` maps each level back to your text. See [answers](/arc/reference/decisions-api#answers), and [examples](/arc/decisions-api/examples) for more question shapes.
</Step>
<Step title="Inspect the request">
Find the request in [usage](/platform/usage) with the tokens it was billed for.
</Step>
</Steps>

## Python

```python
import os
import requests

def ask(state, questions, model="arc-1.0"):
    response = requests.post(
        "https://api.rayline.ai/v1/decisions",
        headers={"Authorization": f"Bearer {os.environ['RAYLINE_API_KEY']}"},
        json={"model": model, "state": state, "questions": questions},
        timeout=30,
    )
    if response.status_code != 200:
        # Decisions errors are {"error": "<code>", "detail": {...}}
        raise RuntimeError(f"{response.status_code}: {response.text}")
    return response.json()["answers"]

answers = ask(
    "The new dashboard is so much faster. Great work, team!",
    {"sentiment": {
        "type": "choice",
        "instructions": "What is the sentiment of this message?",
        "criteria": {"positive": None, "neutral": None, "negative": None},
    }},
)
print(answers["sentiment"]["choice"])  # positive
```

## TypeScript

```typescript
type Question =
  | { type: "noul"; instructions?: string; criteria?: { true?: string; false?: string } }
  | { type: "choice"; instructions?: string; criteria: Record<string, string | null> }
  | { type: "score"; instructions?: string; criteria: string[] };

async function ask(state: unknown, questions: Record<string, Question>, model = "arc-1.0") {
  const response = await fetch("https://api.rayline.ai/v1/decisions", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.RAYLINE_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ model, state, questions }),
    signal: AbortSignal.timeout(30_000),
  });
  if (!response.ok) {
    // Decisions errors are {"error": "<code>", "detail": {...}}
    throw new Error(`${response.status}: ${await response.text()}`);
  }
  return (await response.json()).answers;
}

const answers = await ask(
  "The new dashboard is so much faster. Great work, team!",
  {
    sentiment: {
      type: "choice",
      instructions: "What is the sentiment of this message?",
      criteria: { positive: null, neutral: null, negative: null },
    },
  },
);
console.log(answers.sentiment.choice); // positive
```

## Next steps

- Retry `429` after `Retry-After`, and `503` with backoff; fix the request on any other error. See [limits and errors](/arc/decisions-api/limits-and-errors).
- Keep a state and its longest question within 32,768 tokens, and ask at most 16 questions a request. See [limits](/arc/decisions-api/limits-and-errors#limits).
- If your organization uses zero data retention, send <code>{decisionsZdrModel}</code> as `model`; for Contributor, <code>{decisionsContributorModel}</code>. See [pricing and privacy](/arc/decisions-api/pricing-and-privacy).
