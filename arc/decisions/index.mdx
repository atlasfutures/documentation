ARC Decisions chooses a model and reasoning configuration for each turn without generating the answer. Use it when you want adaptive selection while keeping control of inference, provider access, and your application's agent loop.

<ArcPreview />

## The loop

For every turn of a conversation:

1. Send the conversation to `POST /v1/routes` with an ARC model ID in `model` and the same `x-conversation-id` as the previous turns.
2. Read `model` and `thinking` from the response.
3. Run the turn on that model, with that reasoning configuration, in your own stack.
4. Append the result to the conversation, handle tools and retries, and repeat.

```python
import os
import requests

ROUTES_URL = "https://api.rayline.ai/v1/routes"
HEADERS = {
    "Authorization": f"Bearer {os.environ['RAYLINE_API_KEY']}",
    "Content-Type": "application/json",
}

def decide(conversation_id: str, system: str, messages: list) -> dict:
    response = requests.post(
        ROUTES_URL,
        headers={**HEADERS, "x-conversation-id": conversation_id},
        json={"model": "arc-swift", "system": system, "messages": messages},
        timeout=10,
    )
    response.raise_for_status()
    return response.json()

decision = decide("task-1842", system_prompt, messages)
# decision["model"]    -> "deepseek/deepseek-v4-pro"
# decision["thinking"] -> {"mode": "off", "budget_tokens": None}
reply = run_on_your_stack(decision["model"], decision["thinking"], system_prompt, messages)
messages.append({"role": "assistant", "content": reply})
```

`run_on_your_stack` is your own dispatch: your provider clients, credentials, and model-ID mapping. To apply the reasoning configuration without breaking prompt caching, see [Applying effort](/arc/decisions/applying-effort). See the [Decisions reference](/arc/reference/decisions) for every request and response field.

## Swift, Sage, or your own value

Every decision includes `presets`: what ARC would choose at ARC Swift's value (V 0.1) and at ARC Sage's value (V 4.5), from one read of your request. Use the preset that matches the trade-off you want, or compare them.

To decide at your own value, request `arc-1.0` with `routing.value_usd`, from 0.1 to 5 US dollars per successful result. The response adds a `custom` result at that value:

```python
json={
    "model": "arc-1.0",
    "messages": messages,
    "routing": {"value_usd": 2, "temperature": 0.3},
}
# decision["presets"]["swift"], decision["presets"]["sage"], decision["custom"]
```

`routing.temperature` makes ARC explore: it draws among candidates instead of always taking the top choice, and reports the probability of what it chose so you can account for it. Decisions requests are never used to train ARC, and exploration happens only when you ask for it.

Check `routing` in the response: each control you sent is `applied` or `unsupported`. Do not treat an `unsupported` control as having changed the decision. Field details are in the [Decisions reference](/arc/reference/decisions#routing-controls).

## Your own prices

ARC selects at Rayline catalog prices unless you send yours. If your inference costs differ, for example because of negotiated rates or your own hardware, send them in `routing.prices`; see [bring your own prices](/arc/decisions/prices).

## Multi-turn conversations

ARC decides each turn in the context of the conversation so far. Send a stable `x-conversation-id` on every turn and ARC:

- Accounts for the models already used, including the cost of leaving a model whose prompt cache is warm. Often the right decision is to stay, and `episode.stayed` tells you when it did.
- Re-uses the context it has already read, so later turns are mostly metered as cache reads.

Use one ID per conversation and one per parallel subagent. A conversation's state expires once it goes idle. See [conversations](/arc/reference/decisions#conversations).

## What you own

Your application owns provider credentials, execution, provider compatibility, retries, and fallback behavior. A successful decision is not a successful generation. If the chosen model is unavailable, handle that explicitly in your integration. `alternatives` lists other models ARC scored, but it is not a fallback order.

Apply `thinking` as returned. ARC scored the model under that reasoning configuration, and the same model with a different configuration is a different choice.

## How billing differs

A decision is billed for the tokens ARC reads to make it, once per request, however many results it returns: the presets, any custom result, and alternatives come from the same read. Decisions has no output-token charge. Your prices change which model ARC selects; they never change what the decision costs. Provider inference is a separate cost, paid through your execution stack. See [ARC pricing](/arc/pricing) and [billing](/platform/billing).
