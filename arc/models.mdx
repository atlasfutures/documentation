ARC chooses a model and reasoning effort for every request. You choose how ARC trades cost against quality by choosing a tier.

| | ARC Swift | ARC Sage |
| --- | --- | --- |
| Model ID | `arc-swift` | `arc-sage` |
| Optimizes for | Lower cost and faster turns | Harder tasks where quality matters more than cost |
| Default for | API quickstarts | Coding tools |
| Billing | Swift's fixed rate card | Sage's fixed rate card |

Each tier has one fixed rate card for input, cache-read, cache-write, and output tokens, whichever model serves the request. See [ARC pricing](/arc/pricing).

Use the ID wherever a tool or API takes a model:

- in a coding tool, as the model in its [tool guide](/tools);
- in the API, as `model` in a [Messages request](/arc/quickstart) or a [decision](/arc/decisions).

Gateways that list Rayline models use the prefixed IDs `rayline/arc-swift` and `rayline/arc-sage`; first-party requests use the bare IDs above.

## Configurable ARC

`arc-1.0` is ARC with your own settings: you choose how much a better result is worth to you and how much ARC explores. It is billed at the served model's catalog price, with no ARC fee. See [configure ARC routing](/arc/gateway-routing).

## Quality claims

Quality comparisons between tiers come from cross-validation on held-out tasks, not from live traffic. See [evaluate ARC](/arc/concepts/evaluation) to measure ARC on your own workload.
