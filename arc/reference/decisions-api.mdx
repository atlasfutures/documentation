```
POST https://api.rayline.ai/v1/decisions
```

ARC answers typed questions about a state you send, in one request, without generating text. See [Decisions API](/arc/decisions-api) for an overview.

## Authentication

Send your Rayline API key (`rlk-...`) in either header:

| Header | Value |
| --- | --- |
| `Authorization` | `Bearer $RAYLINE_API_KEY` |
| `x-api-key` | `$RAYLINE_API_KEY` |

See [API keys](/platform/api-keys).

## Request

A JSON object with these members. Any other member is refused with `400` (`invalid_body`).

| Field | Required | Notes |
| --- | --- | --- |
| `state` | Yes | What the questions are about: any JSON value. See [state](#state). |
| `questions` | Yes | A non-empty object of up to 16 questions, keyed by an ID you choose. See [questions](#questions). |
| `model` | No | `arc-decisions-0.1` (the default when you leave it out), `arc-decisions-zdr-0.1` or `arc-decisions-contributor-0.1`. The ID sets the data mode and the rate card. Any other model returns `404` (`model_not_found`). An organization on zero data retention must use `arc-decisions-zdr-0.1`. |
| `session_id` | No | A string of 1 to 256 characters naming your session. Reserved: it does not change answers today. Any other value returns `422` (`invalid_session_id`). |

```json
{
  "model": "arc-decisions-0.1",
  "state": {
    "system": "You are the support assistant for a project-management app.",
    "messages": [
      {"role": "user", "content": "My March invoice charged me twice for the Pro plan."},
      {"role": "assistant", "content": "Sorry about that. I've refunded the duplicate charge."}
    ]
  },
  "questions": {
    "resolved": {"type": "noul", "instructions": "Has the customer's issue been resolved?"}
  }
}
```

### State

ARC reads `state` as text:

- An object with a `messages` array, or an `input` array, is read as a conversation: one block per message, in order, with an optional top-level `system` first. Each message is an object with a string `role`; its `content` is read as is when it is a string, and as JSON text otherwise. A message without a string `role` returns `400` (`invalid_body`).
- Any other value is read as one user message: a string as is, other JSON as its text.

The state and its longest question must fit within 32,768 tokens; see [limits](#limits).

### Questions

`questions` is an object whose keys are your question IDs (non-empty strings) and whose values are questions. Each question has only these members:

| Member | Required | Notes |
| --- | --- | --- |
| `type` | Yes | `noul`, `choice`, or `score`. |
| `instructions` | No | The question, as a string, object or array. Objects and arrays are read as JSON text. |
| `criteria` | For `choice` and `score` | The options or scale; shape depends on `type`, below. |

| Type | `criteria` |
| --- | --- |
| `noul` | Optional. An object with `true` and/or `false`, each describing what that answer means. |
| `choice` | Required. An object mapping each option name (a non-empty string) to its description, or to `null` for none. 1 to 64 options. |
| `score` | Required. An array of levels, ordered low to high, each a description (not `null`). 1 to 10 levels. |

```json
{
  "is_bug": {"type": "noul", "instructions": "Is the customer reporting a bug?"},
  "team": {
    "type": "choice",
    "instructions": "Which team should own this ticket?",
    "criteria": {"payments": "Checkout, payment and billing problems", "accounts": "Sign-in and user accounts", "docs": null}
  },
  "urgency": {
    "type": "score",
    "instructions": "How urgent is this ticket?",
    "criteria": ["Can wait", "Needs attention this week", "Needs attention today", "Blocking revenue right now"]
  }
}
```

Image questions (`box`) and image `assets` are not supported and return `422` (`question_type_not_supported`).

## Response

```json
{
  "model": "arc-decisions-0.1",
  "answers": {
    "is_bug": {"type": "noul", "noul": 0.6},
    "team": {
      "type": "choice",
      "choice": "payments",
      "confidence": 0.81,
      "probabilities": {"payments": 0.87, "accounts": 0.07, "docs": 0.06}
    },
    "urgency": {
      "type": "score",
      "score": 1.91,
      "confidence": 0.26,
      "legend": {"0": "Can wait", "1": "Needs attention this week", "2": "Needs attention today", "3": "Blocking revenue right now"},
      "probabilities": {"0": 0.11, "1": 0.2, "2": 0.37, "3": 0.33}
    }
  },
  "usage": {"input_tokens": 258, "output_tokens": 0}
}
```

This response is the [ticket triage example](/arc/decisions-api/examples#several-questions-in-one-call), shortened to three of its four answers.

| Field | Type | Description |
| --- | --- | --- |
| `model` | string | The model ID you sent, or `arc-decisions-0.1` if you sent none. |
| `answers` | object | One answer per question, under the question's ID. See [answers](#answers). |
| `usage.input_tokens` | integer | The tokens ARC read: your state plus every question. This is what the request is billed for; see [ARC pricing](/arc/pricing#decisions-api). |
| `usage.output_tokens` | integer | Always `0`. |
| `usage.input_tokens_details.cached_tokens` | integer | May appear: input ARC reused from an earlier request. Cached tokens are billed at the same rate as other input tokens. |

### Answers

Every answer carries its question's `type`.

| Type | Field | Meaning |
| --- | --- | --- |
| `noul` | `noul` | The probability, from 0 to 1, that the answer is true. |
| `choice` | `choice` | The option name with the highest probability. |
| | `probabilities` | Each option name's probability; they sum to 1. |
| | `confidence` | From 0 to 1: 0 when every option is equally likely, 1 when one option has all the probability. Computed as `(p_max - 1/n) / (1 - 1/n)` over `n` options; 1 when there is one option. |
| `score` | `score` | The expected level: the probability-weighted mean of the level indexes, from `0` (your first level) to `n - 1`. |
| | `probabilities` | Each level's probability, keyed `"0"` to `"n-1"`; they sum to 1. |
| | `legend` | Each level's key mapped to the text you sent. |
| | `confidence` | From 0 to 1: how concentrated the probabilities are around the most likely level, relative to a uniform spread. |

Probabilities are calibrated per question type. Read them as estimates and set your own thresholds for the decisions you make from them.

## Limits

| Limit | Value |
| --- | --- |
| Questions per request | 16 |
| State plus the longest question | 32,768 tokens, counted by ARC's tokenizer; `422` (`state_too_long`) reports the count |
| One question | 8,192 tokens |
| `choice` options | 1 to 64 |
| `score` levels | 1 to 10 |
| `session_id` | 256 characters |
| Rate | 30 requests per minute per account, across all of its keys, counted separately from the Routes API |

A request normally completes within about a second. ARC answers all of a request's questions in one read of the state, so adding questions costs their own tokens, not another read of the state.

## Errors

Decisions errors use this body, with a stable `error` code:

```json
{"error": "state_too_long", "detail": {"tokens": 39612, "max_tokens": 32768}}
```

Two refusals use the Anthropic format instead, `{"type": "error", "error": {"type": "...", "code": "...", "message": "..."}}`: `use_routes_endpoint` and `decisions_not_available`. Both are answered before your key is checked.

| Status | `error` | Meaning | Retry? |
| --- | --- | --- | --- |
| `400` | `use_routes_endpoint` (Anthropic format) | The body has no top-level `questions`: it is a route lookup | No; send it to [`POST /v1/routes`](/arc/reference/routes) |
| `400` | `invalid_body` | The body is not JSON, has no `state`, has a member other than `model`, `state`, `questions` and `session_id`, `model` is not a string, or a `state` message has no string `role` | No; fix the request |
| `401` | `authentication_error` | Missing or invalid API key. `detail.message` says which | No |
| `402` | `billing_error` | The workspace has no balance to pay for the request. `detail.message` links to the top-up page | No; [add funds](/platform/billing#which-balance-pays) |
| `403` | `zdr_model_required` | The organization uses zero data retention and `model` is not `arc-decisions-zdr-0.1`. `detail.model` names the ID to use | No; use that ID |
| `403` | `contributor_models_off` | `model` is `arc-decisions-contributor-0.1` and **Allow Contributor models** is off for the organization | No |
| `404` | `model_not_found` | `model` is not a Decisions model ID. `detail.model` echoes it | No |
| `404` | `decisions_not_available` (Anthropic format) | The Decisions API is not enabled on this host | No |
| `422` | `invalid_question` | `questions` is empty or not an object, a question is malformed, a question is over its token limit, or there are more than 16 questions (`detail.reason` `too_many_questions`, `detail.max` 16). `detail.question` names the question when one is at fault | No; fix the question |
| `422` | `question_type_not_supported` | A `box` question, or image `assets` | No |
| `422` | `state_too_long` | The state plus its longest question is over the limit. `detail.tokens` is the count; `detail.max_tokens` the limit | No; shorten the state |
| `422` | `invalid_session_id` | `session_id` is not a string of 1 to 256 characters. `detail.max_length` is 256 | No |
| `429` | `rate_limited` | Rate limit reached. `detail.retry_after_s` and the `Retry-After` header give the wait | Yes, after `Retry-After` seconds |
| `429` | `capacity` | ARC is at capacity | Yes, with backoff |
| `503` | `question_head_unavailable` | The Decisions API is temporarily unavailable. When it is starting up, the response carries `Retry-After` | Yes, after `Retry-After` or with backoff |

Refused requests are not billed. A request refused with `invalid_body`, `invalid_question`, `question_type_not_supported`, `state_too_long`, `capacity` or `question_head_unavailable` can still count toward the rate limit.

See [errors and limits](/arc/reference/errors) for troubleshooting that applies to every Rayline API.
