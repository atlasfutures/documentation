```
POST https://api.rayline.ai/v1/routes
```

Returns ARC's choice of model and reasoning configuration for a request, without running it. Execute the choice in your own stack.

## Authentication

Send your Rayline API key (`rlk-...`) in either header:

| Header | Value |
| --- | --- |
| `Authorization` | `Bearer $RAYLINE_API_KEY` |
| `x-api-key` | `$RAYLINE_API_KEY` |

See [API keys](/platform/api-keys).

## Request

Send the same body you would send to generate the turn, in any of three formats: [Anthropic Messages](https://docs.anthropic.com/en/api/messages), OpenAI Chat Completions, or OpenAI Responses. The fields below use the Messages names; Chat Completions and Responses bodies use their own equivalents (`messages` or `input`).

| Field | Required | Notes |
| --- | --- | --- |
| `messages` | Yes | A non-empty array of messages. ARC reads the whole conversation you send. |
| `system` | No | Your system prompt. |
| `tools` | No | Accepted. See the `tools_not_encoded` and `tool_schemas_not_encoded` [warnings](#warnings). |
| `model` | Yes | An ARC model ID: `arc-swift`, `arc-sage`, or `arc-1.0`. The prefixed `rayline/arc-swift` and `rayline/arc-sage` are accepted aliases. A request that names a provider model returns `409` (`non_arc_lookup`); an unknown `arc-*` ID returns `400` (`unknown_model`). |
| `routing` | No | ARC's [routing controls](#routing-controls): your value, routing temperature, and prices. |
| `max_tokens`, `temperature`, `stream` | No | Ignored. A decision is always returned as a single JSON response. |

ARC reads the format from the body. A body without a format-specific field is read as Anthropic Messages. To state the format, send the `x-rayline-format` header with `anthropic`, `chat`, or `responses`.

### Routing controls

`routing` is an object. Every member is optional; a member Rayline does not recognise is refused with `400` (`routing_unknown_member`), never ignored.

| Member | Type | Meaning |
| --- | --- | --- |
| `value_usd` | number, 0.1 to 5 | Your V: what one successful result is worth to you, in US dollars. Adds a [`custom`](#custom-and-routing-echo) result decided at this value. Out-of-range values are refused, never clamped. With `arc-swift` or `arc-sage` it must equal the tier's fixed V (0.1 or 4.5), or the request is refused with `tier_value_immutable`; use `arc-1.0` for your own value. |
| `temperature` | number, 0 or more | Routing temperature: a softmax temperature over ARC's normalized scores for each result. 0 always takes the top choice. Uncapped on Decisions. Separate from the model's generation `temperature`. |
| `prices` | object | Your inference prices: up to 256 model IDs, each with `input`, `cache_read`, `cache_write`, and `output` in USD per million tokens. All four are required; 0 is a price, a missing leg is an error. They change which model ARC selects, never what the decision costs. See [bring your own prices](/arc/decisions/prices). |
| `exclusive` | boolean | `true` limits the candidates to the models in `prices`. Requires `prices`. |

```json
{
  "model": "arc-1.0",
  "messages": [{"role": "user", "content": "Review a database migration for data-loss risks."}],
  "routing": {
    "value_usd": 2,
    "temperature": 0.5,
    "prices": {
      "deepseek/deepseek-v4-pro": {"input": 0.4, "cache_read": 0.04, "cache_write": 0.4, "output": 0.9},
      "anthropic/claude-sonnet-5": {"input": 3, "cache_read": 0.3, "cache_write": 3.75, "output": 15}
    },
    "exclusive": true
  }
}
```

Decisions requests are never used to train ARC.

### Conversation headers

| Header | Purpose |
| --- | --- |
| `x-rayline-format` | Optional: `anthropic`, `chat`, or `responses`, when the body alone does not show its format. An unrecognized value is ignored. |
| `x-conversation-id` | A stable ID for the conversation. Send the same value on every turn so each decision accounts for the conversation so far. See [Conversations](#conversations). |

See [Conversation identity](#conversation-identity) for how the conversation ID is resolved.

## Response

```json
{
  "route_id": "rt_5f0c9a2e8b1d4c7fa6e3b2d19c8a7f60",
  "object": "route",
  "model": "deepseek/deepseek-v4-pro",
  "worker": "deepseek/deepseek-v4-pro@thinking-off",
  "provider": "openrouter",
  "thinking": { "mode": "off", "budget_tokens": null },
  "checkpoint": "arc-c82-dev.c82a1f3e",
  "alternatives": [
    {
      "model": "xiaomi/mimo-v2.5-pro",
      "worker": "xiaomi/mimo-v2.5-pro@thinking-on",
      "provider": "openrouter",
      "score": 0.62
    }
  ],
  "selected_pricing": {
    "input_per_mtok": 0.435,
    "output_per_mtok": 0.87,
    "cache_read_per_mtok": 0.003625,
    "cache_write_per_mtok": 0.435
  },
  "warnings": [],
  "episode": { "turn_index": 4, "stayed": true },
  "usage": { "encoded_input_tokens": 1840, "cache_read_tokens": 1200 },
  "latency_ms": 212,
  "presets": {
    "swift": {
      "model": "deepseek/deepseek-v4-pro",
      "worker": "deepseek/deepseek-v4-pro@thinking-off",
      "provider": "openrouter",
      "thinking": { "mode": "off", "budget_tokens": null },
      "value_usd": 0.1,
      "cost_weight": 10,
      "prices": { "basis": "catalog", "price_sha256": null }
    },
    "sage": {
      "model": "xiaomi/mimo-v2.5-pro",
      "worker": "xiaomi/mimo-v2.5-pro@thinking-on",
      "provider": "openrouter",
      "thinking": { "mode": "on", "budget_tokens": 8192 },
      "value_usd": 4.5,
      "cost_weight": 0.2222222222222222,
      "prices": { "basis": "catalog", "price_sha256": null }
    }
  }
}
```

| Field | Type | Description |
| --- | --- | --- |
| `route_id` | string | Identifies this decision. Include it when you contact support. |
| `object` | string | Always `route`. |
| `model` | string | The model to run. |
| `worker` | string | The model and configuration ARC scored, for example `xiaomi/mimo-v2.5-pro@thinking-on`. Two workers can share one model with different reasoning settings. |
| `provider` | string | The provider the worker is configured for. Omitted when the worker names none. |
| `thinking` | object | The reasoning configuration the choice was scored under. `mode` is `on` or `off`. `budget_tokens` is the reasoning budget, or `null` when thinking is off. Apply it as given: the choice was scored for this configuration, not for the model alone. |
| `thinking_level` | string | Present when the decision includes a per-turn steering level, for example `up`, `down`, or `none`. Apply it as a private steering instruction; see [Applying effort](/arc/decisions/applying-effort). |
| `checkpoint` | string | The ARC checkpoint that made the decision. |
| `alternatives` | array | Other workers ARC scored and did not choose, highest score first, each with `model`, `worker`, `provider`, and `score`. Workers excluded by a hard constraint are not listed. This is not a fallback order. |
| `baseline` | object | A reference `model` and its rate card (`input_per_mtok`, `output_per_mtok`, `cache_read_per_mtok`, `cache_write_per_mtok`), for comparing cost. Omitted when the checkpoint declares no reference. |
| `selected_pricing` | object | The chosen worker's rate card, in USD per million tokens. |
| `warnings` | array of strings | Always present, usually empty. See [Warnings](#warnings). |
| `episode` | object | Present when the request carried a [conversation ID](#conversation-identity). `turn_index` counts the conversation's turns. `stayed` is `true` when ARC kept the previous turn's worker. |
| `usage` | object | `encoded_input_tokens` and `cache_read_tokens`: the tokens ARC read to make this decision, once for all results. These are the metered quantities; see [ARC pricing](/arc/pricing). `cache_read_tokens` is 0 until Decisions reuses cached prefixes. |
| `latency_ms` | integer | Time ARC spent deciding. |
| `presets` | object | The decisions at ARC Swift and ARC Sage. See [Presets](#presets). |
| `custom` | object | Present when you sent `routing.value_usd`. See [Custom and routing echo](#custom-and-routing-echo). |
| `routing` | object | Present when you sent `routing`. |

ARC does not return a confidence score or an explanation.

### Presets

Every response carries `presets`, with the decision at both fixed tiers, from the same single read of your request:

| Field | Meaning |
| --- | --- |
| `presets.swift` | The decision at ARC Swift's value (V 0.1). |
| `presets.sage` | The decision at ARC Sage's value (V 4.5). |

Each result has `model`, `worker`, `provider`, `thinking`, `thinking_level`, `value_usd`, `cost_weight` (1 / `value_usd`), `prices`, and, when you sent `routing.temperature`, `temperature`.

- `prices.basis` is `catalog` (Rayline catalog prices) or `caller` (your `routing.prices`, identified by `prices.price_sha256`).
- `temperature` reports `requested`, `applied`, and `status`: `greedy` (you asked for 0), `applied` (ARC drew the model at the `applied` temperature; `propensity` is the probability of the chosen model, and `pi` lists each candidate's probability), `not_applied` (with a `reason`), or `unsupported` (the serving path did not confirm it, so the result is the top choice).

The top-level `model`, `worker`, and `thinking` are the decision for the `model` you requested. Presets are alternatives: running one does not change the conversation's state.

### Custom and routing echo

| Field | Present when | Meaning |
| --- | --- | --- |
| `custom` | You sent `routing.value_usd` | The decision at your value, with the same fields as a preset. |
| `routing` | You sent `routing` | Each member you sent, with `status` `applied` or `unsupported`. `routing.prices` also reports `price_sha256`, `exclusive`, and the priced `models`. `unapplied_keys` lists every member that was not applied. |

Treat `unsupported` as not applied: ARC decided without that control, and the result says so rather than showing your value as used.

### Usage

`usage.encoded_input_tokens` and `usage.cache_read_tokens` count one read of your request, however many results the response carries. That read is what a decision is billed for; see [ARC pricing](/arc/pricing).

## Conversations

Send the same `x-conversation-id` on every turn of a conversation. ARC then:

- Decides each turn in light of the turns before it, including whether to stay on the current model. Switching models mid-conversation can discard a provider's prompt cache, and ARC accounts for that cost.
- Re-uses the context it already encoded, so a later turn is mostly reported as `cache_read_tokens` rather than `encoded_input_tokens`.

Without a conversation ID, each request is decided on its own and the response has no `episode`.

Keep one ID per conversation. For parallel subagents, give each subagent its own ID. Send one request per conversation at a time: a second concurrent request for the same conversation returns `429` until the first completes.

A conversation's state expires after a period of inactivity.

### Conversation identity

ARC takes the conversation ID from the first of these that is present:

1. The `x-conversation-id` header.
2. The `x-claude-code-session-id` header, which Claude Code sends on its own.

With neither, the request is stateless.

The body field `metadata.user_id` is not read. Anthropic defines it as a per-user identifier, and one ID for every conversation of a user would decide those conversations in each other's context. Send `x-conversation-id` to identify the conversation.

The same order applies to a routed turn, so a lookup and the turn it precedes land on the same episode.

## Warnings

Each warning is a string of the form `code: explanation`. Treat the code as stable and the explanation as display text.

| Code | Meaning |
| --- | --- |
| `format_inferred` | The body had no field unique to one format, so ARC inferred it. Send `x-rayline-format` to state it. |
| `tools_not_encoded` | The request's tools did not influence this decision. |
| `tool_schemas_not_encoded` | Tool names influenced this decision; their descriptions and schemas did not. |
| `checkpoint_not_pinned` | A requested checkpoint was ignored; the served checkpoint made the decision. |

## Errors and limits

Errors use the Anthropic error format: `{"type": "error", "error": {"type": "...", "message": "..."}}`.

Each error carries a stable `error.code`.

| Status | `error.code` | Meaning | Retry? |
| --- | --- | --- | --- |
| `400` | `invalid_body`, `unknown_model` | The body is not a JSON object with messages, or names an unknown ARC ID | No; fix the request |
| `400` | `routing_invalid`, `routing_unknown_member` | `routing` is not an object, or has a member Rayline does not support | No |
| `400` | `value_invalid`, `value_out_of_bounds`, `tier_value_immutable` | `routing.value_usd` is not a number in 0.1–5, or differs from a tier's fixed V | No |
| `400` | `temperature_invalid` | `routing.temperature` is not a finite number of 0 or more | No |
| `400` | `prices_invalid`, `price_leg_missing`, `price_leg_invalid`, `unknown_price_model` | `routing.prices` is malformed, misses a leg, has a negative or non-finite price, or names a model ARC cannot select | No |
| `400` | `exclusive_invalid`, `exclusive_without_prices` | `routing.exclusive` is not a boolean, or has no `prices` | No |
| `401` | | Missing or invalid API key | No |
| `402` | `insufficient_funds` | The workspace cannot pay for the decision | No; add funds |
| `404` | `model_not_served` | The ARC model is not serving in this environment | No |
| `409` | `non_arc_lookup` | The request names a provider model, not an ARC model | No; set `model` to an ARC ID |
| `413` | | The request body is too large | No |
| `429` | `rate_limited` | Rate limit reached, or the conversation already has a request in progress | Yes, after `Retry-After` seconds |
| `502` | `inconsistent_upstream` | The routing service returned an inconsistent answer | Yes, with backoff |
| `503` | `unavailable` | Decisions is temporarily unavailable | Yes, with backoff |
| `504` | `timeout` | The decision did not complete in time | Yes, with backoff |
| `529` | `capacity` | ARC is at capacity | Yes, with backoff |

Each account can make 30 decision requests per minute across all of its keys. A decision normally completes within about 1.5 seconds.

See [ARC Decisions](/arc/decisions) for the integration loop and [errors and limits](/arc/reference/errors) for troubleshooting.
