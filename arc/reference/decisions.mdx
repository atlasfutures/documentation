```
POST https://api.rayline.ai/v1/routes
```

Returns ARC's choice of model and reasoning configuration for a request, without running it. Execute the choice in your own stack.

## Authentication

Send your Rayline API key (`rlk-...`) in either header:

| Header | Value |
| --- | --- |
| `Authorization` | `Bearer $RAYLINE_API_KEY` |
| `x-api-key` | `$RAYLINE_API_KEY` |

See [API keys](/platform/api-keys).

## Request

Send the same body you would send to generate the turn, in any of three formats: [Anthropic Messages](https://docs.anthropic.com/en/api/messages), OpenAI Chat Completions, or OpenAI Responses. The fields below use the Messages names; Chat Completions and Responses bodies use their own equivalents (`messages` or `input`).

| Field | Required | Notes |
| --- | --- | --- |
| `messages` | Yes | A non-empty array of messages. ARC reads the whole conversation you send. |
| `system` | No | Your system prompt. |
| `tools` | No | Read with your system prompt: ARC encodes each tool's name, description and schema, and those tokens count in `usage.encoded_input_tokens`. |
| `model` | Yes | An ARC model ID: `arc-swift`, `arc-sage`, or `arc-1.0`. The prefixed `rayline/arc-swift` and `rayline/arc-sage` are accepted aliases. A request that names a provider model returns `409` (`non_arc_lookup`); an unknown `arc-*` ID returns `400` (`unknown_model`). |
| `routing` | No | ARC's [routing controls](#routing-controls): your value, routing temperature, prices, routing policy, and opt-in predictions. |
| `max_tokens`, `temperature`, `stream` | No | Ignored. A decision is always returned as a single JSON response. |

ARC reads the format from the body. A body without a format-specific field is read as Anthropic Messages. To state the format, send the `x-rayline-format` header with `anthropic`, `chat`, or `responses`.

### Routing controls

`routing` is an object. Every member is optional; a member Rayline does not recognise is refused with `400` (`routing_unknown_member`), never ignored.

| Member | Type | Meaning |
| --- | --- | --- |
| `value_usd` | number, 0.1 to 5 | Your V: what one successful result is worth to you, in US dollars. Adds a [`custom`](#custom-and-routing-echo) result decided at this value. Out-of-range values are refused, never clamped. With `arc-swift` or `arc-sage` it must equal the tier's fixed V (0.1 or 4.5), or the request is refused with `tier_value_immutable`; use `arc-1.0` for your own value. |
| `temperature` | number, 0 or more | Routing temperature: a softmax temperature over ARC's normalized scores for each result. 0 always takes the top choice. Uncapped on Decisions. Separate from the model's generation `temperature`. |
| `prices` | object | Your inference prices: up to 256 model IDs, each with `input`, `cache_read`, `cache_write`, and `output` in USD per million tokens. All four are required; 0 is a price, a missing leg is an error. They change which model ARC selects, never what the decision costs. See [bring your own prices](/arc/decisions/prices). |
| `exclusive` | boolean | `true` limits the candidates to the models in `prices`. Requires `prices`. |
| `price_profile_id` | string | A saved price profile from your organization, used instead of `prices`. Send one or the other, never both. See [price profiles](/arc/decisions/prices#price-profiles). |
| `price_profile_version` | integer, 1 or more | Pins a saved profile version. Omit it to use the profile's current version. Requires `price_profile_id`. |
| `response_fields` | array | Opt-in response members. The only value is `["predictions"]`: each result adds its [`model_choice`](#predictions) and the response adds the offered `candidates`. |
| `policy` | object | A versioned [routing policy](#routing-policy) preset with optional overrides. Omit it for today's behaviour. |
| `execution` | object | For executors, not people: the execution facts of a caller that runs turns itself (`arc-execution-context.v2`). [Rayline Local](/arc/decisions/hybrid-local) fills it in. It changes only that caller's results and is never billed, stored, or trained on. |

<Note>
`policy`, `execution`, `response_fields`, and saved price profiles are in preview and are not yet accepted by `api.rayline.ai`. Until they are, a production request that sends one is refused or has the member reported `unsupported`.
</Note>

```json
{
  "model": "arc-1.0",
  "messages": [{"role": "user", "content": "Review a database migration for data-loss risks."}],
  "routing": {
    "value_usd": 2,
    "temperature": 0.5,
    "prices": {
      "deepseek/deepseek-v4-pro": {"input": 0.4, "cache_read": 0.04, "cache_write": 0.4, "output": 0.9},
      "anthropic/claude-sonnet-5": {"input": 3, "cache_read": 0.3, "cache_write": 3.75, "output": 15}
    },
    "exclusive": true
  }
}
```

Decisions requests are never used to train ARC.

### Routing policy

`routing.policy` names how ARC may change the model and the reasoning configuration over a conversation. It has one required member, `preset`, and optional `overrides`:

```json
"routing": {
  "policy": {
    "preset": "arc-policy.prefer-local.v1",
    "overrides": {
      "schedule": {"model": ["cache_boundaries", "user_messages"], "thinking": ["all_turns"]},
      "selection": {"min_p_pass": 0.55}
    }
  }
}
```

| Preset | Behaviour |
| --- | --- |
| No `policy` | Exactly today's behaviour: the same decisions, response, and billing as before policies existed. |
| `arc-policy.package-default.v1` | Today's behaviour, named explicitly. |
| `arc-policy.hybrid-default.v1` | Utility selection. The model may change at cache boundaries, the reasoning configuration on every turn, and a request that no longer fits its current target is handed to one that does. Rayline Local sends this preset by default. |
| `arc-policy.prefer-local.v1` | As hybrid-default, but at a model switch point ARC chooses an offered local target when its predicted pass probability is at least `min_p_pass` (default 0.65) and, if set, its predicted rest-of-episode tokens are at most `max_rest_tokens`. Otherwise utility selection decides over the cloud targets. With no local target it is the same as utility selection. |

**Schedule overrides.** `overrides.schedule` sets, per dimension (`model` and `thinking`), the set of switch-point classes at which that dimension may change. At any other turn the dimension holds: the same model, or the same reasoning configuration. An omitted dimension keeps the preset's schedule.

| Class | A turn matches when |
| --- | --- |
| `cache_boundaries` | Task start, subagent start, compaction, or a typed user turn whose cache is observed cold. Unknown cache state counts as warm. |
| `user_messages` | Any typed user turn. |
| `all_turns` | Any turn, including tool results. |

The hybrid-default and prefer-local presets use model `["cache_boundaries"]` and thinking `["all_turns"]`. A forced handoff when the current target no longer fits is always allowed, outside the schedule. A class the serving checkpoint does not support for that dimension is refused with `policy_schedule_not_admitted`; switching models at `all_turns` is not supported by current checkpoints.

**Selection overrides.** `overrides.selection` sets prefer-local's thresholds: `min_p_pass`, from 0 to 1, and `max_rest_tokens`, a positive integer or omitted for no budget. They are refused with `policy_invalid` on any other preset.

`policy` is accepted on Decisions only. A generation request that sends it is refused with `policy_not_supported`. A deployment may limit the presets it serves; an unlisted preset is refused with `policy_preset_not_admitted`.

The local and capacity behaviour depends on the facts in `routing.execution`, which an executor such as Rayline Local supplies. Without them, a preset changes only the schedule. See [hybrid local and cloud routing](/arc/decisions/hybrid-local).

### Conversation headers

| Header | Purpose |
| --- | --- |
| `x-rayline-format` | Optional: `anthropic`, `chat`, or `responses`, when the body alone does not show its format. An unrecognized value is ignored. |
| `x-conversation-id` | A stable ID for the conversation. Send the same value on every turn so each decision accounts for the conversation so far. See [Conversations](#conversations). |

## Response

```json
{
  "route_id": "rt_5f0c9a2e8b1d4c7fa6e3b2d19c8a7f60",
  "object": "route",
  "model": "deepseek/deepseek-v4-pro",
  "worker": "deepseek/deepseek-v4-pro@thinking-off",
  "provider": "openrouter",
  "thinking": { "mode": "off", "budget_tokens": null },
  "checkpoint": "arc-c82-dev.c82a1f3e",
  "alternatives": [
    {
      "model": "xiaomi/mimo-v2.5-pro",
      "worker": "xiaomi/mimo-v2.5-pro@thinking-on",
      "provider": "openrouter",
      "score": 0.62
    }
  ],
  "selected_pricing": {
    "input_per_mtok": 0.435,
    "output_per_mtok": 0.87,
    "cache_read_per_mtok": 0.003625,
    "cache_write_per_mtok": 0.435
  },
  "warnings": ["episode_not_tracked: this cell keeps no episodes for route lookups, so the conversation did not influence this route"],
  "usage": { "encoded_input_tokens": 3040, "cache_read_tokens": 0 },
  "latency_ms": 212,
  "presets": {
    "swift": {
      "model": "deepseek/deepseek-v4-pro",
      "worker": "deepseek/deepseek-v4-pro@thinking-off",
      "provider": "openrouter",
      "thinking": { "mode": "off", "budget_tokens": null },
      "value_usd": 0.1,
      "cost_weight": 10,
      "prices": { "basis": "catalog", "price_sha256": null }
    },
    "sage": {
      "model": "xiaomi/mimo-v2.5-pro",
      "worker": "xiaomi/mimo-v2.5-pro@thinking-on",
      "provider": "openrouter",
      "thinking": { "mode": "on", "budget_tokens": 8192 },
      "value_usd": 4.5,
      "cost_weight": 0.2222222222222222,
      "prices": { "basis": "catalog", "price_sha256": null }
    }
  }
}
```

| Field | Type | Description |
| --- | --- | --- |
| `route_id` | string | Identifies this decision. Include it when you contact support. |
| `object` | string | Always `route`. |
| `model` | string | The model to run. |
| `worker` | string | The model and configuration ARC scored, for example `xiaomi/mimo-v2.5-pro@thinking-on`. Two workers can share one model with different reasoning settings. |
| `provider` | string | The provider the worker is configured for. Omitted when the worker names none. |
| `thinking` | object | The reasoning configuration the choice was scored under. `mode` is `on` or `off`. `budget_tokens` is the reasoning budget, or `null` when thinking is off. Apply it as given: the choice was scored for this configuration, not for the model alone. |
| `thinking_level` | string | Present when the decision includes a per-turn steering level, for example `up`, `down`, or `none`. Apply it as a private steering instruction; see [Applying effort](/arc/decisions/applying-effort). |
| `checkpoint` | string | The ARC checkpoint that made the decision. |
| `alternatives` | array | Other workers ARC scored and did not choose, highest score first, each with `model`, `worker`, `provider`, and `score`. Workers excluded by a hard constraint are not listed. This is not a fallback order. |
| `baseline` | object | A reference `model` and its rate card (`input_per_mtok`, `output_per_mtok`, `cache_read_per_mtok`, `cache_write_per_mtok`), for comparing cost. Omitted when the checkpoint declares no reference. |
| `selected_pricing` | object | The chosen worker's rate card, in USD per million tokens. |
| `warnings` | array of strings | Always present. Until Decisions keeps conversations, every lookup carries `episode_not_tracked`. See [Warnings](#warnings). |
| `episode` | object | Reserved for conversation tracking, which Decisions does not yet do; absent today (see [conversations](#conversations)). When present, `turn_index` counts the conversation's turns and `stayed` is `true` when ARC kept the previous turn's worker. |
| `usage` | object | `encoded_input_tokens` and `cache_read_tokens`: the tokens ARC read to make this decision, once for all results. These are the metered quantities; see [ARC pricing](/arc/pricing). `cache_read_tokens` is 0 until Decisions reuses cached prefixes. |
| `latency_ms` | integer | Time ARC spent deciding. |
| `presets` | object | The decisions at ARC Swift and ARC Sage. See [Presets](#presets). |
| `custom` | object | Present when you sent `routing.value_usd`. See [Custom and routing echo](#custom-and-routing-echo). |
| `routing` | object | Present when you sent `routing`. |
| `candidates` | array | Present when you requested `predictions`: every model offered to this request, each with its `model`, `effort`, and `prediction`. |
| `candidates_context` | object | Present with `candidates`: the decision point (`boundary`), the selector that scored them (`selector_id`), and the package hash. |

ARC does not return an explanation. It returns its own success predictions only when you ask for them; see [Predictions](#predictions).

### Presets

Every response carries `presets`, with the decision at both fixed tiers, from the same single read of your request:

| Field | Meaning |
| --- | --- |
| `presets.swift` | The decision at ARC Swift's value (V 0.1). |
| `presets.sage` | The decision at ARC Sage's value (V 4.5). |

Each result has `model`, `worker`, `provider`, `thinking`, `thinking_level`, `value_usd`, `cost_weight` (1 / `value_usd`), `prices`, and, when you sent `routing.temperature`, `temperature`. When you requested predictions it adds `model_choice`, and when you sent `routing.policy` or `routing.execution` it adds a [`receipt`](#receipt).

- `prices.basis` is `catalog` (Rayline catalog prices) or `caller` (your `routing.prices`, identified by `prices.price_sha256`).
- `temperature` reports `requested`, `applied`, and `status`: `greedy` (you asked for 0), `applied` (ARC drew the model at the `applied` temperature; `propensity` is the probability of the chosen model, and `pi` lists each candidate's probability), `not_applied` (with a `reason`), or `unsupported` (the serving path did not confirm it, so the result is the top choice).

The top-level `model`, `worker`, and `thinking` are the decision for the `model` you requested. Presets are alternatives: running one does not change the conversation's state.

### Custom and routing echo

| Field | Present when | Meaning |
| --- | --- | --- |
| `custom` | You sent `routing.value_usd` | The decision at your value, with the same fields as a preset. |
| `routing` | You sent `routing` | Each member you sent, with `status` `applied` or `unsupported`. `routing.prices` also reports `price_sha256`, `exclusive`, and the priced `models`. `unapplied_keys` lists every member that was not applied. |

Treat `unsupported` as not applied: ARC decided without that control, and the result says so rather than showing your value as used.

### Predictions

Send `"response_fields": ["predictions"]` to see the numbers behind a choice. Each result adds `model_choice`:

```json
"model_choice": {
  "model": "claude-haiku-5.5",
  "effort": null,
  "prediction": {
    "success": 0.94,
    "success_head": "stage_one_p_pass",
    "tokens": {"input": 1407, "cache_read": 1, "cache_write": 0, "output": 4910},
    "cost_usd": 0.0026,
    "horizon": "rest_of_episode"
  }
}
```

- `success` is ARC's predicted probability that the task passes on this model, from the first-stage selector (`success_head: stage_one_p_pass`). It is a prediction, not a guarantee.
- `tokens` are the predicted tokens for the rest of the episode (`horizon: rest_of_episode`), per billed leg.
- `cost_usd` prices those tokens in the result's price world: your prices when they were applied, otherwise catalog prices. It is `null` when any leg it needs is unknown.
- On a turn where the model was held, no first-stage choice is made: `model_choice` is `null` and `candidates` is absent.

Any value ARC could not compute is `null`, never 0. The `routing.response_fields` echo reports `applied` or `unsupported`. Predictions do not change the decision or its charge.

### Receipt

When you send `routing.policy` or `routing.execution`, each result carries a `receipt` that says how it was decided. Requests without either are unchanged and carry no receipt.

```json
"receipt": {
  "action_id": "<sha256>",
  "control_id": "<sha256>",
  "policy": "arc-policy.hybrid-default.v1",
  "decided_by": {"model": "capacity_handoff", "thinking": "schedule"},
  "eligible": {"model": null, "thinking": "all_turns"},
  "held_from": "<sha256>",
  "excluded": [{"action_id": "<sha256>", "reason": "context_capacity"}],
  "capacity_unknown": [],
  "basis": "marker_inferred"
}
```

| Field | Meaning |
| --- | --- |
| `action_id`, `control_id` | The chosen action (model and reasoning control) and its control. |
| `policy` | The preset applied, or `null`. |
| `decided_by.model` | `schedule` (a switch point allowed a choice), `held` (the model stayed), `capacity_handoff` (the held target no longer fit), `held_unavailable` (the held model was not offered, so ARC chose as at a start), `prefer_local_threshold` or `utility_fallback` (a prefer-local decision), or `null` for a single-stage checkpoint. |
| `decided_by.thinking` | `schedule` or `held`. |
| `eligible` | Per dimension, the schedule class this turn matched, or `null` when it matched none. |
| `held_from` | The action the conversation was on before a handoff, or `null`. |
| `excluded` | Offered actions ARC excluded, with `reason`: `context_capacity`, `runtime_unavailable`, or `capacity_unknown_local`. |
| `capacity_unknown` | Offered actions admitted without a capacity fact. |
| `basis` | Where the turn's event came from: `explicit_client`, `marker_inferred` (inferred from the wire by the executor), `service_inferred`, or `null`. |
| `selection` | Prefer-local decisions only: the rule, `min_p_pass`, `max_rest_tokens`, each local target's `p_pass`, `rest_tokens` and eligibility, and the `outcome`. Absent otherwise. |

The `routing.policy` echo reports `status` (`applied` or `unsupported`) and the `preset` as sent. A policy does not change the Decisions charge.

### Usage

`usage.encoded_input_tokens` and `usage.cache_read_tokens` count one read of your request, however many results the response carries. That read is what a decision is billed for; see [ARC pricing](/arc/pricing).

## Conversations

Decisions does not yet keep conversations: each lookup is decided on its own, as if it were the conversation's first turn, and ARC reads the whole request every time. Every lookup returns the `episode_not_tracked` warning, whether or not it sends a conversation ID; the response has no `episode`, and `usage.cache_read_tokens` is 0.

When conversation tracking ships, sending the same `x-conversation-id` on every turn will let ARC decide each turn in light of the turns before it, including whether to stay on the current model, and re-use the context it already encoded, reported as `cache_read_tokens`. Sending the header today is harmless.

Keep one ID per conversation. For parallel subagents, give each subagent its own ID. Send one request per conversation at a time: a second concurrent request for the same conversation returns `429` until the first completes.

A conversation's state expires after a period of inactivity.

### Conversation identity

ARC takes the conversation ID from the first of these that is present:

1. The `x-conversation-id` header.
2. The `x-claude-code-session-id` header, which Claude Code sends on its own.

With neither, the request is stateless.

The body field `metadata.user_id` is not read. Anthropic defines it as a per-user identifier, and one ID for every conversation of a user would decide those conversations in each other's context. Send `x-conversation-id` to identify the conversation.

The same order applies to a routed turn. Once Decisions keeps conversations, a lookup and the turn it precedes will land on the same episode.

## Warnings

Each warning is a string of the form `code: explanation`. Treat the code as stable and the explanation as display text.

| Code | Meaning |
| --- | --- |
| `format_inferred` | The body had no field unique to one format, so ARC inferred it. Send `x-rayline-format` to state it. |
| `tools_not_encoded` | The request's tools did not influence this decision. Current cells can return this warning even though the tools were encoded and billed; a fix is in progress. |
| `tool_schemas_not_encoded` | Tool names influenced this decision; their descriptions and schemas did not. |
| `episode_not_tracked` | Decisions does not yet keep conversations, so this lookup was decided on its own. Returned on every lookup today, with or without a conversation ID. |
| `checkpoint_not_pinned` | A requested checkpoint was ignored; the served checkpoint made the decision. |

## Errors and limits

Errors use the Anthropic error format: `{"type": "error", "error": {"type": "...", "message": "..."}}`.

Each error carries a stable `error.code`.

| Status | `error.code` | Meaning | Retry? |
| --- | --- | --- | --- |
| `400` | `invalid_body`, `unknown_model` | The body is not a JSON object with messages, or names an unknown ARC ID | No; fix the request |
| `400` | `routing_invalid`, `routing_unknown_member` | `routing` is not an object, or has a member Rayline does not support | No |
| `400` | `value_invalid`, `value_out_of_bounds`, `tier_value_immutable` | `routing.value_usd` is not a number in 0.1–5, or differs from a tier's fixed V | No |
| `400` | `temperature_invalid` | `routing.temperature` is not a finite number of 0 or more | No |
| `400` | `prices_invalid`, `price_leg_missing`, `price_leg_invalid`, `unknown_price_model` | `routing.prices` is malformed, misses a leg, has a negative or non-finite price, or names a model ARC cannot select | No |
| `400` | `exclusive_invalid`, `exclusive_without_prices` | `routing.exclusive` is not a boolean, or has no `prices` | No |
| `400` | `response_fields_invalid` | `routing.response_fields` is not `["predictions"]` | No |
| `400` | `policy_invalid` | `routing.policy` names an unknown preset or class, or sets selection thresholds on a preset without a selection rule | No |
| `400` | `policy_preset_not_admitted`, `policy_schedule_not_admitted` | This deployment does not serve the preset, or the checkpoint does not support a schedule class for that dimension | No; use a supported preset or class |
| `400` | `execution_invalid` and other `execution_*` codes | `routing.execution` is malformed or contradicts the messages | No; report it to the executor's maintainers |
| `409` | `execution_no_feasible_target` | No offered target can run the request | No |
| `401` | | Missing or invalid API key | No |
| `402` | `insufficient_funds` | The workspace cannot pay for the decision | No; add funds |
| `404` | `model_not_served` | The ARC model is not serving in this environment | No |
| `409` | `non_arc_lookup` | The request names a provider model, not an ARC model | No; set `model` to an ARC ID |
| `413` | | The request body is too large | No |
| `429` | `rate_limited` | Rate limit reached, or the conversation already has a request in progress | Yes, after `Retry-After` seconds |
| `502` | `inconsistent_upstream` | The routing service returned an inconsistent answer | Yes, with backoff |
| `503` | `unavailable` | Decisions is temporarily unavailable | Yes, with backoff |
| `504` | `timeout` | The decision did not complete in time | Yes, with backoff |
| `529` | `capacity` | ARC is at capacity | Yes, with backoff |

Each account can make 30 decision requests per minute across all of its keys. A decision normally completes within about 1.5 seconds.

See [ARC Decisions](/arc/decisions) for the integration loop and [errors and limits](/arc/reference/errors) for troubleshooting.
