| HTTP status | Meaning |
| --- | --- |
| 400 | The request body is missing or malformed |
| 401 | Missing or invalid authentication |
| 402 | The workspace has no balance to pay for the request (`error.type` `billing_error`); [add funds](/platform/billing#which-balance-pays) |
| 403 | Access denied for this key or workspace, or the ARC model ID does not fit the organization's data mode (`zdr_model_required`, `contributor_models_off`); see [data and privacy](/platform/data-privacy#arc-model-ids-choose-the-data-mode) |
| 404 | Unsupported method or path |
| 409 | The request conflicts with the state of a resource it names, such as an archived price profile |
| 413 | The request body is too large |
| 429 | Rate limit reached, or a conversation already has a request in progress; wait for `Retry-After` |
| 503 | Temporarily unavailable; retry with backoff |
| 504 | The request did not complete in time; retry with backoff |

Error bodies on the Messages and Routes API endpoints use the Anthropic format, `{"type": "error", "error": {"type": "...", "message": "..."}}`. A `402` looks like this, and its message links to the page where you add funds:

```json
{"type": "error", "error": {"type": "billing_error", "message": "No balance — top up at https://platform.rayline.ai to continue"}}
```
 See the [Routes API reference](/arc/reference/routes#errors-and-limits) for causes and limits specific to the Routes API.

A `404` with `model_not_found` means generation does not accept that model ID: a prefixed ID such as `rayline/arc-swift`, an unknown `arc-*` ID, or the removed `rayline-router`. The Routes API accepts only ARC IDs and refuses any other with `400`: `unknown_model` for a prefixed or unknown `arc-*` ID, `arc_model_required` for a provider model. Check the [tier IDs](/arc/quickstart#choose-a-tier).

## Troubleshooting

- Use the base URL and key for the same environment and workspace.
- Inspect the status and error message without logging your API key.
- Do not retry `400`, `401`, `402`, `403`, `409`, or `413`; fix the request, add funds, or fix access first.
- Retry `429` after the `Retry-After` interval, and `503` or `504` with exponential backoff.

Routes API limits are in the [Routes API reference](/arc/reference/routes#errors-and-limits). The Decisions API uses its own error body, `{"error": "<code>", "detail": {...}}`; see [Decisions API limits and errors](/arc/decisions-api/limits-and-errors).
