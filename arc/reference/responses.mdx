## Conversation identity

A Responses turn takes its conversation ID from the first of these that is present:

1. The `x-conversation-id` header.
2. The body field `prompt_cache_key`, on a request from Codex.

With neither, the turn is stateless.

Codex sets `prompt_cache_key` to its thread ID on every request, and each spawned subagent thread sends its own, so Codex gets multi-turn decisions and separate subagent conversations without any configuration. For any other client the field is a cache-grouping hint that may legitimately be shared across conversations, so it is not read; send `x-conversation-id`. The `user` and `safety_identifier` fields are never read: they identify a user, and one ID for every conversation of a user would decide those conversations in each other's context. See [conversation identity](/arc/reference/decisions#conversation-identity) for the Decisions rules.
