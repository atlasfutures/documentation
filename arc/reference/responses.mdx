## Conversation identity

A Responses turn takes its conversation ID from the first of these that is present:

1. The `x-conversation-id` header.
2. The body field `prompt_cache_key`.

With neither, the turn is stateless.

`prompt_cache_key` is the Responses API's own per-conversation cache key, so a client that already sets it gets multi-turn decisions without a custom header. Codex sends its thread ID there, and each spawned subagent thread sends its own, so parallel subagents are separate conversations without further configuration. The `user` and `safety_identifier` fields are not read: they identify a user, and one ID for every conversation of a user would decide those conversations in each other's context. See [conversation identity](/arc/reference/decisions#conversation-identity) for the Decisions rules.
