ARC Responses is the hosted execution path: ARC chooses a model and reasoning effort, and Rayline returns the answer. You integrate one interface instead of maintaining provider dispatch yourself.

<ArcPreview />

## How it fits your application

1. Send the user's request and the context needed for the task.
2. ARC selects the model and reasoning effort.
3. Rayline runs inference and returns the answer.

Start with the [quickstart](/arc/quickstart). Send Anthropic Messages requests with an ARC tier ID; see the [Responses reference](/arc/reference/responses).

## Responses versus Decisions

Choose [Decisions](/arc/decisions) if you want to retain your own provider connections and execution loop. A Responses call includes routing and generation in its [token pricing](/arc/pricing); it does not add a second Decisions fee.

## Protocols are not products

A client using an OpenAI-style Responses protocol is not necessarily using ARC Responses. For example, Codex can use that protocol through [Agent Gateway](/rules-router/quickstart/codex), where explicit rules select the model.

See the [compatibility matrix](/arc/reference/compatibility) for preview limitations.
