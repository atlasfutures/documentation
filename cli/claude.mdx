## rayline claude

The primary command for most users. Launches Claude Code with Rayline routing, telemetry hooks, and optional local model support — all pre-configured.

```bash
rayline claude
```

### What it does

On a terminal, `rayline claude` configures everything and launches Claude Code in one step:

1. **Signs you in** if needed — opens the browser to `platform.rayline.ai` and provisions a routing key automatically (no manual key handling)
2. **Starts a local routing proxy** that forwards Claude Code's API traffic to Rayline's router and injects your key. Claude Code keeps talking to its normal Anthropic-compatible endpoint; the proxy handles routing transparently
3. **Installs telemetry hooks** that track per-route cost and model selection (visible in the dashboard and the Rayline app)
4. **Sets up the Rayline app** on first run (macOS Apple Silicon, unless opted out)
5. **Launches Claude Code** with all the above configured

<Note>
Because routing happens through the local proxy, `rayline claude` does **not** set `ANTHROPIC_BASE_URL` in your environment — it sets `HTTPS_PROXY` and a trusted CA instead. To confirm routing, use the dashboard or `rayline claude --diagnose`, not `echo $ANTHROPIC_BASE_URL`. The raw environment-variable approach is covered under [Claude Code Setup](/quickstart/claude-code#advanced-manual-environment-variables).
</Note>

### Passing arguments to Claude Code

Any arguments `rayline claude` doesn't recognize are forwarded straight to Claude Code:

```bash
rayline claude --resume                # forward a standard Claude Code flag
rayline claude -- --some-claude-flag   # everything after -- is passed through verbatim
```

### Options

These flags are interpreted by `rayline`; everything else is forwarded to Claude Code.

| Flag | Description |
|---|---|
| `--local` | Route eligible requests to an on-device model. See [On-Device Routing](/how-it-works/on-device) |
| `-m, --model <model>` | Pin the main agent to a specific model |
| `--env <name>` | Environment (`prod` or `dev`). Default: `prod` |
| `--diagnose` | Print the routing configuration before launching |
| `--auto-compact-window <tokens>` | Override Claude Code's auto-compact threshold |
| `--no-statusline` | Hide the picked-model status line in Claude Code |
| `--no-telemetry` | Disable hook telemetry for this run |

### Setup subcommands

#### rayline claude setup

Run the interactive setup wizard for Claude Code integration:

```bash
rayline claude setup
```

Configures hooks, validates credentials, and verifies connectivity.

#### rayline claude hooks install

Install Rayline's telemetry hooks into Claude Code's hook system:

```bash
rayline claude hooks install
```

Hooks capture per-route data (model selected, tokens, cost) and forward it to the dashboard. They're installed automatically by `rayline claude` but can be managed independently.

#### rayline claude hooks status

Check if hooks are installed and active:

```bash
rayline claude hooks status
```

#### rayline claude hooks uninstall

Remove Rayline hooks from Claude Code:

```bash
rayline claude hooks uninstall
```

#### rayline claude login

Authenticate specifically for Claude Code integration (alias for `rayline auth login` with Claude-specific setup):

```bash
rayline claude login
```

#### rayline claude key

Print the stored routing key (`rlk-…`) — handy for the [manual env-var setup](/quickstart/claude-code#advanced-manual-environment-variables):

```bash
rayline claude key
```

#### rayline claude logout

Remove Claude Code-specific credentials:

```bash
rayline claude logout
```

### Telemetry

Hooks installed by `rayline claude` send non-sensitive metadata to Rayline for cost tracking:

- Which model was selected for each route
- Token counts (input, output, cache)
- Latency
- Task classification

No code, prompts, or responses are captured. Opt out with:

```bash
export RAYLINE_HOOK_OPT_OUT=1
```
