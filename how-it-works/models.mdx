Rayline routes across model families from multiple providers through a single endpoint. You don't need separate API keys for each provider — Rayline handles authentication and dispatch.

## On-device models

Run locally on your machine via MLX (Apple Silicon) or llama-server. Zero token cost, zero latency to provider, full privacy.

| Model | Runtime | Notes |
|---|---|---|
| Qwen 3.6 35B A3B (Q4_K_M) | MLX / llama-server | Default on-device model. Strong code quality, runs well on 32GB+ M-series Macs |

The default on-device model is downloaded automatically when you run `rayline router start`. See [Local Models Guide](/guides/local-models) for setup and custom model configuration.

<Note>
On-device routing is always free — zero token cost, zero markup. The model runs on your hardware.
</Note>

## Provider routing

You don't choose providers directly — Rayline handles provider selection as part of routing. Each model has a primary provider and a fallback:

- **Anthropic** models route directly to Anthropic's API
- **OpenAI** models route to OpenAI
- **DeepSeek** models route through Fireworks (primary) or OpenRouter (fallback)
- **GLM** models route through Z.ai, which speaks the Anthropic Messages API natively
- **Kimi, Qwen, MiniMax** route through OpenRouter
- **On-device** models route through the local `rld` daemon

## Model catalog updates

The model catalog is managed server-side and can be updated without a client release. When new models are added to Rayline, they become available to Arc-1 for routing immediately. You can see the current catalog in your [dashboard settings](https://platform.rayline.ai/settings).

## Using a specific model

If you want to force a specific model for certain task types, use [routing settings](/guides/routing-settings) to override individual slots. For example, you could pin "Complex" tasks to Claude Opus while letting everything else route via ML.
