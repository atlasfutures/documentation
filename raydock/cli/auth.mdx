Run these commands from your terminal:

```bash
raydock auth login
raydock auth status
```

For a machine without a browser, use `raydock auth login --no-browser` for device-code login. Use `--paste` when you need to paste a browser callback URL manually.

You can also skip this step: on a terminal, `raydock claude` and `raydock codex` start the sign-in flow when they need it. `raydock status` is the same as `raydock auth status`.

## Sign out

```bash
raydock auth logout
```

This command requests revocation of the stored Rayline session and removes its stored router key. If it reports that remote revocation failed, follow up in the platform. It does not revoke every independently created workspace API key. Manage those in [API keys](/platform/api-keys).

## Scripting

`raydock auth token` prints an account bearer token. Treat it as a secret; do not paste it into logs or support tickets. An account token is not a substitute for the routing API key in the manual client setup.

Your sign-in session and the router key that hosted launches create are stored in `~/.config/rayline/credentials.json`, separately for each [hosted environment](/raydock/cli#hosted-environment). Commands that need an account token also read it from the `RAYLINE_AUTH_TOKEN` environment variable, or from `--auth-token <token>` before the command.

Use `raydock auth --help` and the [CLI source](https://github.com/rayline-ai/rayline) for the commands supported by your installed release.
