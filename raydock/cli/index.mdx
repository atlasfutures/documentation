Use `raydock` for new commands. The previous `rayline` command remains a supported alias; configuration and credentials stay in their existing locations.


<span id="install" />
<span id="update" />


Raydock ships the `raydock` CLI, the `rld` daemon, and the `rayline-core` execution core, with `rayline` as an alias for the CLI. The CLI starts `rld` when a session needs it; you do not run `rld` yourself.

Install the latest release on macOS or Linux:

```bash
curl -fsSL https://get.rayline.ai/install.sh | bash
```

On Windows, in PowerShell:

```powershell
irm https://get.rayline.ai/install.ps1 | iex
```

The installers download the Raydock CLI, `rld` daemon, and `rayline-core` execution core, verify them against the release checksums, and install `raydock` plus the `rayline` alias in `~/.rayline/bin`. They then add that directory to your `PATH`:

- on macOS and Linux, by appending `export PATH="$HOME/.rayline/bin:$PATH"` to `~/.zshrc`, `~/.bash_profile` on macOS, or `~/.bashrc` on Linux, depending on your shell;
- on Windows, in your user `PATH`.

Open a new terminal afterwards. With another shell, the installer prints the line to add yourself.

| Variable | Effect |
| --- | --- |
| `RAYLINE_INSTALL_DIR` | Install into another directory. On macOS and Linux the installer then leaves your shell profile alone; add the directory to your `PATH` yourself. |
| `RAYLINE_NO_PATH_UPDATE=1` | Skip the `PATH` change. |

To install a specific version, pass its full version string, as `raydock --version` prints it (for example `0.2.8+108012255153`), to the script with `curl -fsSL https://get.rayline.ai/install.sh | bash -s -- <version>`. On Windows, set `RAYLINE_VERSION` before running the installer.

Check the install and keep it current:

```bash
raydock --version
raydock update --check
raydock update
```

`raydock update` also accepts `--version <version>`, `--force`, and `--dry-run`, which downloads and verifies a release without replacing your binary.

## Migrating from Rayline Local

For an installation at 0.2.14, run the old updater, then invoke it once more to finish creating the canonical command:

```bash
rayline update
rayline --version
raydock --version
```

The migration notice is written to stderr. Both command names then use the same implementation and preserve arguments, output, and exit status.

For Homebrew, run `brew update` and `brew upgrade raydock`. The tap’s formula rename migrates existing `rayline` installations. New installs use `brew install rayline-ai/tap/raydock`.

## Commands

| Command | Purpose |
| --- | --- |
| `raydock auth login` | Sign in for hosted routing. See [raydock auth](/raydock/cli/auth). |
| `raydock status` | Show your sign-in state. Same as `raydock auth status`. |
| `raydock claude` | Launch Claude Code with hosted routing. See [raydock claude](/raydock/cli/claude). |
| `raydock claude --local` | Launch Claude Code with the on-device hybrid router. |
| `raydock codex -- exec "summarize this repo"` | Run Codex CLI through Rayline. See [Codex](/tools/codex). |
| `raydock codex app` | Launch the Codex desktop app through Rayline. |
| `raydock codex configure` | Write a reusable Codex profile that points at the local router. |
| `raydock opencode`, `pi`, `omp`, `hermes`, `openclaw` | Launch another agent harness through hosted routing. See [more agent harnesses](/tools/more-tools). |
| `raydock local <command>` | Choose and manage the local model. See [local models](/raydock/local-models). |
| `raydock router <command>` | Start, inspect, or stop the local runtime. See [raydock router](/raydock/cli/router). |
| `raydock top` | Show live request metrics for the local runtime. |
| `raydock update` | Check for or install a CLI update. |

Every command accepts `--help`. Run `raydock --help` for the list your installed version supports.

## Hosted environment

Hosted commands use the production service at `https://api.rayline.ai` by default. `--env <name>` selects another hosted environment, which must be defined under `environments` in `~/.config/rayline/settings.json`. Most users never need it. Put it before the command or directly after it:

```bash
raydock --env <name> claude
raydock claude --env <name>
```

Sign-in sessions and router keys are stored per environment, so signing in to one does not sign you in to another.

## Files

| Path | Contents |
| --- | --- |
| `~/.rayline/bin` | The `raydock` command, `rayline` alias, `rld`, and `rayline-core`. |
| `~/.rayline/rld` | Local runtime state and logs. |
| `~/.rayline/cc` | Claude Code configuration for `--isolated` sessions. |
| `~/.rayline/codex-app-home` | The isolated Codex home used by `raydock codex app`. |
| `~/.config/rayline/credentials.json` | Your Rayline sign-in session and router key. Treat it as a secret. |
| `~/.config/rayline/settings.json` | Local model choice, subagent mapping, and environment definitions. |

## Ports

The local runtime listens on `127.0.0.1` only.

| Port | Used by | Override |
| --- | --- | --- |
| 20810 | Transparent proxy for Claude Code and Anthropic SDK clients | `RAYLINE_PROXY_PORT` |
| 20812 | Proxy for `--isolated` Claude Code sessions | `RAYLINE_ISOLATED_PROXY_PORT` |
| 20811 | Local router, including the OpenAI Responses endpoint for Codex | |
| 20809 | Request injector | `RAYLINE_INJECTOR_PORT` |
| 20808 | Adapter in front of the local model server | |
| 20813 | Request metrics for `raydock top` | `RAYLINE_METRICS_PORT` |
| 20814 | Request metrics for `--isolated` sessions | `RAYLINE_ISOLATED_METRICS_PORT` |

From Rayline 0.2.8, if port 20813 is already taken when `raydock codex` starts its router, Rayline picks a free port instead, and `raydock top` still finds it. If another program already uses one of the other ports, see [port conflicts](/raydock/troubleshooting/connectivity#port-conflicts).
