Client launch commands normally start the runtime for you. To inspect an existing session:

```bash
rayline router status
rayline router logs --lines 120
rayline top --json
```

Logs can include sensitive request information. Review and redact them before sharing.

## Start a runtime separately

```bash
rayline router start --help
```

Choose `--mode anthropic` or `--mode codex` for the inbound protocol. Use `--config <path>` for explicit endpoints and routes. Configure on-device providers through `rayline local`; the old model-repository and adapter-port flags are not the current setup interface.

Use the [current source guide](https://github.com/rayline-ai/rayline/blob/main/docs/getting-started.md) for complete client wiring. Starting a daemon alone does not reconfigure an already running client.

<span id="rl-router-stop" />

## Stop

```bash
rayline router stop
```

Stop only when sessions using that runtime can be interrupted. Clients still pointing to it will fail until it is restarted or their configuration changes.
