## Choosing a local model

The quickest setup is the interactive wizard, which `rayline claude --local` also runs on first use:

```bash
rayline local onboard
```

### Option 1 — Rayline runs the model

```bash
rayline local models
rayline local use <number|model-id>
```

`rayline local models` lists recommended models with how well each fits your hardware, plus models from local servers it detects. Rayline downloads the selected model on first use and serves it through its bundled runtime.

### Option 2 — you run the model

For a server you manage, test it and then configure the endpoint and model explicitly:

```bash
rayline local test --url http://127.0.0.1:11434 --model <model-id>
rayline local custom --url http://127.0.0.1:11434 --model <model-id>
```

Check the server's protocol and model capabilities against the current Rayline configuration. See [Rayline for agents](/rules-router/quickstart/agents) for SDK examples.

### All local commands

| Command | Purpose |
| --- | --- |
| `rayline local onboard [--reset]` | Set up or re-pick the model for `rayline claude --local`. |
| `rayline local models [--json]` | List recommended and detected models with hardware fit. |
| `rayline local download <model-id>` | Download a recommended model without selecting it. |
| `rayline local use <number\|model-id>` | Select a model, downloading it first if needed. |
| `rayline local remove <model-id>` | Delete a downloaded model from disk. |
| `rayline local custom --url <url> --model <name>` | Use a model server you run. |
| `rayline local test --url <url> --model <name>` | Check that a server answers in a compatible format. |
| `rayline local show` | Show the configured mode, endpoint, and account routing state. |
| `rayline local clear` | Remove the local model configuration. |
| `rayline local on`, `rayline local off` | Turn local routing on or off for your signed-in account. |
| `rayline local subagents [--json] [--all]` | Choose which of your Claude Code subagents run locally. |

### Choose which subagents run locally

`rayline local subagents` scans your Claude Code history for the subagents you use and lets you send each one to the local model or the cloud. Read-only agents start out selected for local. Your choices are saved to `~/.config/rayline/settings.json` and apply on the next `rayline claude --local` launch. `--json` prints the list without prompting.

## Hybrid by default

The default Claude Code local session keeps the main agent on cloud Claude and routes eligible subagent work locally. “Local router” does not mean all prompts remain on-device. Use `--route all` for an intentionally fully local route, subject to model support.

Local routing itself needs no Rayline account. Your main-agent cloud provider may still need credentials and charge for inference.

## Operational checks

Allow time and disk space for the first model download. Check available memory, endpoint health, and the configured model before starting a large session. Local inference has hardware and electricity costs even when there is no hosted token charge.

In proxy mode, Rayline creates a local certificate authority so its proxy can read Claude Code's HTTPS traffic, and gives that certificate to Claude Code through `NODE_EXTRA_CA_CERTS`. It does not add the certificate to your system trust store. Read the [security and responsibility notes](https://github.com/rayline-ai/rayline#disclaimers) before using it on a managed machine.

Local config is distinct from the hosted platform's Agent Gateway slots. See [routing policies](/rules-router/policies).
