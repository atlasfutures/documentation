Codex connects to Rayline's local OpenAI Responses router on `http://127.0.0.1:20811/v1`. This path uses plain HTTP on your machine, with no proxy certificate. Install Codex and the [Rayline CLI](/rules-router/cli) first.

## Codex CLI

```bash
rayline codex -- exec "summarize this repo"
```

Rayline starts the router, points Codex at it for this run, and passes everything after `--` to Codex. Put Rayline options before `--`.

## Choose who serves the requests

`--auth` decides where the main agent's requests go:

| Option | Requests go to | Billed through |
| --- | --- | --- |
| `--auth auto` (default) | Hosted Agent Gateway, for the main agent and subagents | Your Rayline workspace |
| `--auth subscription`, or `--subscription` | Your existing ChatGPT/Codex login for the main agent; subagents go to your local model when one is configured | Your ChatGPT plan |
| `--auth none` | Local endpoints only, from your local model or `--config` | Nothing hosted |

The default needs a Rayline sign-in. If you have not signed in, run `rayline auth login`. With `--config <path>`, `auto` follows the routes in that file instead. Use `--model <model>` to request a specific model; without it, the router chooses per request.

```bash
rayline codex --subscription -- exec "summarize this repo"
```

## Codex desktop

```bash
rayline codex app
rayline codex app ~/projects/app
rayline codex app --subscription
```

`rayline codex app` takes the same options as `rayline codex`, plus an optional workspace path. It runs the app on an isolated Codex home, `~/.rayline/codex-app-home`, so your normal Codex configuration is untouched. The first launch copies your existing Codex settings; later launches update only the Rayline routing. The desktop app is single-instance: if it is already running with different routing, the launcher asks before restarting it.

## Reusable profile

To configure Codex yourself instead of launching it through Rayline, write a profile and start the router separately:

```bash
rayline codex configure
rayline router start --mode codex --auth subscription
```

`rayline codex configure` writes `rayline.config.toml` to `$CODEX_HOME`, or to `~/.codex` when `CODEX_HOME` is not set. It accepts `--model`, `--base-url`, and `--auth subscription|none`.

## How your key is handled

From Rayline 0.2.8, Codex never receives your router key. Its provider points at the local router, which holds the key and adds it to hosted requests; subscription mode uses your ChatGPT login. Rayline removes `RAYLINE_ROUTER_API_KEY` from Codex's environment, so the key cannot reach the shell snapshots Codex saves to disk.

If the Codex desktop app was already running before you updated Rayline, quit and relaunch it once. `rayline codex app` reuses a running app whose routing is current, and a running process keeps the environment it started with.

## Manual setup (without the launcher)

The launcher runs a local router between Codex and Agent Gateway. You can instead point Codex straight at the hosted Responses API. Create a key in **API Keys** on the [Rayline platform](https://platform.rayline.ai/keys) and load it into `RAYLINE_KEY` from your secrets manager; see [API keys](/platform/api-keys). Then add the provider to `~/.codex/config.toml`:

```toml
[model_providers.rayline]
name = "Rayline"
base_url = "https://api.rayline.ai/v1"
env_key = "RAYLINE_KEY"
wire_api = "responses"
```

Create a profile that selects it, `~/.codex/rayline.config.toml`:

```toml
model_provider = "rayline"
model = "rayline-router"
```

Start Codex with the profile:

```bash
codex --profile rayline exec "Reply with the word ready."
```

- `env_key` names the variable that holds the key; Codex sends it as a bearer token and never stores it in the config.
- `wire_api = "responses"` makes Codex call `/v1/responses`.
- Current Codex releases read profiles from `<name>.config.toml` in the Codex home and reject a `[profiles.<name>]` table in `config.toml`. If you set `CODEX_HOME`, put both files there.
- Codex sends its thread ID as `prompt_cache_key`, and Agent Gateway uses that as the conversation ID for Codex requests, so you do not need to add a conversation header.
- This is hosted routing only. Subscription mode and local models need the launcher's local router.

Then find the request in [Inspect routed requests](/rules-router/guides/dashboard).

## Explicit routes

Custom configurations can select local or API endpoints, or hosted Agent Gateway routes. See the [CLI configuration guide](https://github.com/rayline-ai/rayline/blob/main/docs/getting-started.md) for the schema.

Hosted Codex traffic uses `/v1/responses` and rules-based selection. The Responses protocol does **not** mean it uses the ARC Responses product.

## Verify

```bash
rayline router status
rayline router logs --lines 120
rayline top
```

Check the configured endpoint and the selected route before assuming a session is local, using a subscription, or charged through Rayline.
