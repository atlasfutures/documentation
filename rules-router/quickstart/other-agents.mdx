## Use ARC with your agent harness

Follow your tool’s guide to connect to the Rayline platform. Each guide also explains its Rayline Local option. Both paths can use cloud inference; see [hosted and local connections](/tools/hosted-local).

Rayline can launch these agent harnesses against hosted Agent Gateway, the same way `rayline claude` does. Install the agent first; Rayline configures the route but does not bundle the agent.

| Command | Agent | Install | Guide |
| --- | --- | --- | --- |
| `rayline opencode` | [opencode](https://opencode.ai) | [opencode install docs](https://opencode.ai/docs/#install) | [opencode](/rules-router/quickstart/other-agents/opencode) |
| `rayline pi` | [pi](https://pi.dev) | [pi install docs](https://github.com/earendil-works/pi#getting-started) | [pi](/rules-router/quickstart/other-agents/pi) |
| `rayline omp` | [oh-my-pi](https://omp.sh) | [oh-my-pi install docs](https://github.com/can1357/oh-my-pi#install) | [oh-my-pi](/rules-router/quickstart/other-agents/omp) |
| `rayline hermes` | [Hermes Agent](https://hermes-agent.nousresearch.com) | [Hermes Agent install docs](https://hermes-agent.nousresearch.com/docs/getting-started/installation) | [Hermes Agent](/rules-router/quickstart/other-agents/hermes) |
| `rayline openclaw` | [OpenClaw](https://openclaw.ai) | [OpenClaw install docs](https://docs.openclaw.ai/install) | [OpenClaw](/rules-router/quickstart/other-agents/openclaw) |

```bash
rayline auth login
rayline pi
rayline opencode run --standalone "summarize this repo"
```

## Launcher options

Everything after the agent's name goes to the agent unchanged, including `--help`. Rayline reads only two options, and only when they come directly after the agent's name, before any of the agent's own arguments:

| Option | Purpose |
| --- | --- |
| `--env <name>` | Use another [hosted environment](/rules-router/cli#hosted-environment). You can also put it before the agent's name. |
| `--auth-token <token>` | Use this account token instead of your stored sign-in. |

Use `--` to pass an argument that would otherwise be read as a Rayline option.

## What the launcher does

1. Signs you in and creates a router key if you have none, as `rayline claude` does. In a non-interactive shell, run `rayline auth login` first.
2. Writes a Rayline config for the agent to `~/.config/rayline/harness/<agent>/<env>/`, readable only by you on macOS and Linux, and points the agent at it through the agent's own config variable. Your normal configuration for that agent is not changed.
3. Starts the agent with `arc-sage-1.0` as its main model and `arc-swift-1.0` for its background roles, where the agent has them. The provider also lists `rayline-router`, which routes through your Agent Gateway rules; select it through the agent's own model option or picker. The agent is told each model has a 200,000-token context window and up to 32,000 output tokens.

Each launch prints the router URL, the environment, and the config directory. Rayline rewrites the files it owns on every launch, so edit the agent's settings through its own files, not Rayline's; each agent's guide lists which files those are.

## How your key is handled

Since Rayline 0.2.12, the launcher writes the router key only into the Rayline-owned config directory, readable only by you, and removes `RAYLINE_KEY` and `RAYLINE_ROUTER_API_KEY` from the agent's environment, so the agent's tools never see the key. Each agent's guide says how its config refers to the key. To use a specific workspace key instead of the stored one, export `RAYLINE_ROUTER_API_KEY` before launching.

## Conversations

Agent Gateway groups requests into conversations. Rayline recognises the session identifiers these agents send on every request, and groups a session's requests into one conversation from those, so a session resumed in a new launch keeps its conversation. Where an agent sends no session identifier, Rayline derives one from the conversation's content. Each agent's guide says which applies.

## Manual setup (without the launcher)

You can connect each agent to Agent Gateway yourself, with the configuration `rayline <agent>` writes. The manual configs read your key from the `RAYLINE_API_KEY` environment variable, the variable used across the Rayline docs; the launcher instead keeps the key in its own config files. Each agent's guide has a copy-paste config. They all rely on two environment variables.

### The API key

Create a key in **API Keys** on the [Rayline platform](https://platform.rayline.ai/keys); see [API keys](/platform/api-keys). Export it as `RAYLINE_API_KEY` in the shell that starts the agent, for example from your secrets manager:

```bash
export RAYLINE_API_KEY="<your Rayline API key>"
```

Every config below refers to `RAYLINE_API_KEY` by name, using the agent's own environment-variable syntax, so the key is never written into a config file. Do not paste the key into the config itself.

### The conversation ID

You do not need to send a conversation ID yourself. Rayline recognises the
session identifiers these agents already send on every request, and groups a
session's requests into one conversation from those; where an agent sends none,
Rayline derives an ID from the conversation's content. Requests grouped this way are routed
together, pinned to the same provider backend where a provider supports that
(so prompt-cache reuse holds), and counted together in usage.

### Check the connection

After setting up an agent, send a short prompt such as `Reply with the word ready.` You should get a reply, and the request should appear with its selected model in [Inspect routed requests](/platform/usage). An authentication error usually means `RAYLINE_API_KEY` is missing from the agent's environment or holds the wrong key.

## Troubleshooting

- **`<agent>` not found on PATH.** Install the agent and make sure its binary is on your `PATH`; the error includes an install hint. On Windows, Rayline also finds `.exe`, `.cmd`, `.bat`, and `.com` files.
- **Sign-in errors in scripts.** Run `rayline auth login` once on a terminal, then check `rayline status`.
- **The agent uses another model.** Check whether a project-level config for that agent overrides the provider or model.

## Use ARC

The launchers start each agent on `arc-sage-1.0`, with `arc-swift-1.0` for background roles, and offer `rayline-router` as well. In manual setup, request an ARC tier by model ID: `arc-sage-1.0` for challenging coding and agent tasks, or `arc-swift-1.0` as a fast workhorse for everyday tasks, with the base URL each guide gives. opencode needs its `/v1` base URL. Check [usage](/platform/usage) after your first task.
