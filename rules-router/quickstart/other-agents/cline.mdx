Cline reaches ARC through its **OpenAI Compatible** provider, either directly
or through a Rayline Local gateway on your machine. The two differ only in the
base URL and the API key.

## Direct API

Cline installs three ways: as a native desktop app, as an extension inside an
IDE (VS Code, Cursor, JetBrains, Windsurf and others), or as a CLI. This guide
configures the **IDE extension**, shown in VS Code; see the
[Cline install page](https://docs.cline.bot/getting-started/installing-cline)
for the others. Open **Cline → Settings → API Configuration** and enter:

| Setting | Value |
| --- | --- |
| API Provider | **OpenAI Compatible** |
| Base URL | `https://api.rayline.ai/v1` |
| API Key | Your [Rayline API key](/platform/api-keys) |
| Custom Model ID | `arc-sage-1.0`, or `arc-swift-1.0` |
| Context Window Size | `200000` for this configuration |
| Max Output Tokens | `2048`; increase for longer responses |
| Supports Images | Off for text-only tasks |
| Reasoning Effort | **None** |

If ARC is absent from the model list, enter its bare ID in **Custom Model ID**.
Under **Custom Headers**, add `x-conversation-id` with a new UUID for each
unrelated task. Keep the same value while continuing a task.

<Note>
The **Custom Headers** step is specific to the IDE extension. Cline's CLI
(install exactly `cline` with `npm install -g cline`; the package named
`@cline/cli` is a different, stale tool) reaches ARC with the same provider, model and base URL via
`cline auth -p openai-compatible -k <key> -m arc-sage -b https://api.rayline.ai/v1`,
but has no custom-header setting, so `x-conversation-id` does not apply to it:
Rayline then derives a conversation from the request itself, so a task still
holds together, but you cannot name a conversation yourself. The desktop app's
settings have not been checked against ARC.
</Note>

![Cline API Configuration with the Rayline platform URL and ARC Sage custom model ID](/images/tools/setup/cline-direct-settings.webp)

Enter your own Rayline API key in the API key field.

Click **Done**, then start a **New Task**. Existing tasks can retain their
previous provider configuration.

## Rayline Local

Use Rayline Local **0.2.12 or later**. The settings are the same as Direct;
only the base URL and the key change, because the gateway holds your real
Rayline key and Cline gets a placeholder. ARC selection and inference remain in
the cloud; nothing runs on your device.

1. Configure the [cloud-forwarding gateway](/tools/hosted-local#configure-a-cloud-forwarding-gateway).
2. In Cline's **API Configuration**, keep **OpenAI Compatible** and the ARC
   model ID from the Direct setup, and change:

| Setting | Value |
| --- | --- |
| Base URL | `http://127.0.0.1:23811/v1` (use your gateway's port) |
| API Key | `local-client` (a non-secret placeholder) |

3. Open **Settings → Features**, turn **Web Search** off, click **Done**, and
   start a **New Task**.

![Cline Features settings with Web Search turned off](/images/tools/setup/cline-web-search.webp)

<Warning>
Keep **Web Search** off for this configuration. Cline's provider-native
search tool is unsupported by ARC. Ordinary file tools work with search disabled. The setting applies to new tasks.
</Warning>

## Try your first task

Open your project and ask: **Read the README and explain how to run this project.**
Choose **ARC Sage** for a challenging task or switch to **ARC Swift** for everyday work.
You can see the model ARC selected and the request’s cost in [Rayline Usage](/platform/usage).

## Troubleshooting

- **Old provider still used:** start a new task after changing API settings.
- **Local authentication error:** confirm the explicit model mapping and the
  gateway's real API key; `local-client` is only a loopback placeholder.
- **Repeated 503 with Anthropic:** disable **Web Search** and start a new task.
- **404 on the Local Chat Completions path:** your gateway is older than
  0.2.12, which added inbound Chat Completions. Update Rayline Local.

See Cline's [OpenAI-compatible provider reference](https://docs.cline.bot/provider-config/openai-compatible)
for its custom endpoint and model fields.
