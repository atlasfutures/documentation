Use **ARC Sage** (`arc-sage-1.0`) for challenging coding and agent tasks, or **ARC Swift** (`arc-swift-1.0`) as a fast workhorse for everyday tasks. Connect to the Rayline platform with the configuration below.

Install the tool using its [installation guide](https://hermes-agent.nousresearch.com/docs/getting-started/installation) before you begin.

## Connect to the Rayline platform

Set `RAYLINE_API_KEY` first, as described in [manual setup](/rules-router/quickstart/other-agents#manual-setup-without-the-launcher). Use Hermes v2026.9.21 or later; earlier releases do not send the conversation header.

Add these providers to `~/.hermes/config.yaml`, and point `model` at the first one:

```yaml
model:
  provider: "custom:rayline-anth"
  default: "arc-sage-1.0"
  context_length: 200000
providers:
  rayline-anth:
    api_mode: "anthropic_messages"
    base_url: "https://api.rayline.ai"
    key_env: "RAYLINE_API_KEY"
    models:
      arc-sage-1.0:
        context_length: 200000
  rayline-resp:
    api_mode: "codex_responses"
    base_url: "https://api.rayline.ai/v1"
    key_env: "RAYLINE_API_KEY"
    models:
      arc-sage-1.0:
        context_length: 200000
```

- `key_env` names the variable that holds the key; Hermes expands `${NAME}` in other values.
- `rayline-anth` uses the Messages API at `/v1/messages`, so its `base_url` has no `/v1`. `rayline-resp` uses the Responses API at `/v1/responses`, so its `base_url` ends in `/v1`. The Rayline platform does not yet serve ARC on the Responses API, so use `rayline-anth` for ARC Sage and ARC Swift; keep `rayline-resp` for when [Responses support](/arc/availability) arrives.
- The launcher also sets `fallback_providers: []`, so a failed request is not retried against another provider. Add it if you want the same behaviour.

To keep this separate from your normal Hermes home, save it as `config.yaml` in another directory and set `HERMES_HOME` to that directory, as the launcher does.

Check it with `hermes -z "Reply with the word ready."`.

## Use a Rayline Local gateway

[Start a cloud-forwarding gateway](/tools/hosted-local#configure-a-cloud-forwarding-gateway). In the Messages provider configuration, replace the base URL with your gateway’s URL, without `/v1`. Use `http://127.0.0.1:23811` for the linked gateway setup and `RAYLINE_API_KEY=local-client` in the client. The gateway holds your Rayline API key.

## Try your first task

From your project directory, run:

```bash
hermes --provider rayline-anth --model arc-sage-1.0 -z "Read the README and explain how to run this project."
```

To use Swift, add `arc-swift-1.0` to the provider’s models using the same settings as Sage, then select it in your command. View requests and the model ARC selected in [Rayline Usage](/platform/usage).

## Launcher availability

The launcher instructions below require Rayline 0.2.12 or later.

## Install

Install Hermes Agent from its [install docs](https://hermes-agent.nousresearch.com/docs/getting-started/installation). Use v2026.9.21 or later. Then sign in to Rayline:

```bash
rayline auth login
```

## Run

```bash
rayline hermes
rayline hermes --provider rayline-resp --model rayline-router
rayline --env <name> hermes
```

Everything after `hermes` goes to Hermes unchanged. See [launcher options](/rules-router/quickstart/other-agents#launcher-options).

## What Rayline writes

Rayline sets `HERMES_HOME` to `~/.config/rayline/harness/hermes/<env>/` and writes `config.yaml` there on every launch. It defines two providers, both with model `rayline-router`:

| Provider | API | Use |
| --- | --- | --- |
| `rayline-anth` | Anthropic Messages | The default |
| `rayline-resp` | OpenAI Responses | Select with `--provider rayline-resp --model rayline-router` |

Fallback providers are turned off, so a failed request is not retried against another provider. Hermes keeps its sessions, memories, and skills in `HERMES_HOME`, so they are separate from your normal Hermes setup.

## Key handling

The launcher writes the key as each provider's `api_key` in the Rayline-owned `config.yaml`, readable only by you, and removes it from Hermes' environment. A manual config names the variable instead, with `key_env: RAYLINE_API_KEY`.

## Conversations

Each launch is one Agent Gateway conversation; the launcher sends a per-launch conversation id. In manual setup, Rayline recognises the session id Hermes sends on every request, so a conversation holds together on its own.

Hermes releases before v2026.9.21 ignore extra headers on the Messages API. With those releases, every turn on the default provider is a separate conversation. Upgrade to v2026.9.21 or later.

## Known limitations

- Sessions, memories, and skills from your normal Hermes home are not available under `rayline hermes`.
- Edits to Rayline's `config.yaml` are lost on the next launch.

## Troubleshooting

- **`hermes` not found on PATH.** Install Hermes Agent and check `which hermes`.
- **Every turn is a separate conversation.** On a Hermes release before v2026.9.21, upgrade to v2026.9.21 or later.
- See also [shared troubleshooting](/rules-router/quickstart/other-agents#troubleshooting).
