Use **ARC Sage** (`arc-sage`) for coding, or **ARC Swift** (`arc-swift`) for a faster, lower-cost tier. You can connect directly to Rayline or send requests through a Rayline Local gateway. Both paths below use cloud inference.

<Note>
Live dev validation, **21 October 2026**: oh-my-pi **18.12.6** completed two file-reading tasks on each path, one with Sage and one with Swift. Local used an **unreleased Rayline 0.2.10 source build**. Production, launchers, resume, compaction, and extensions were not covered by these checks.
</Note>

## Choose a connection

| Path | Configuration | Gateway required? |
| --- | --- | --- |
| Direct API | Rayline's API base URL and your Rayline API key | No |
| Rayline Local | Your gateway's loopback URL and client authentication | Yes; the gateway holds the upstream Rayline key |

See [what “local” means](/tools/hosted-local). A local gateway does not imply on-device inference or locally running ARC.

## Use ARC directly

Use the [manual configuration below](#manual-setup-without-the-launcher), then replace `rayline-router` with `arc-sage` in the provider's model definition and default model settings. To make Swift available too, duplicate the model definition with ID `arc-swift` and name `ARC Swift`.

Run a specific tier with:

```bash
omp --model rayline/arc-sage
omp --model rayline/arc-swift
```

Assign your chosen tier to all four `modelRoles` if background and planning calls should use it too.

## Use a Rayline Local gateway

First configure a gateway that forwards `arc-sage` and `arc-swift` to your Rayline endpoint. Keep its upstream key in the gateway process environment. In this tool's manual provider configuration, change only:

| Setting | Direct production API | Local gateway used in the dev smoke |
| --- | --- | --- |
| `baseUrl` | `https://api.rayline.ai` | `http://127.0.0.1:23811` |
| `RAYLINE_KEY` | Your Rayline API key | `local-client` for this test gateway |

The port and client authentication depend on your gateway. `23811` is a test port, not a Rayline default. Never send your real Rayline key to an unfamiliar local listener. The upstream dev endpoint used in validation was `https://api-dev.rayline.ai`.

## Verify your setup

Create a file named `receipt.txt` containing:

```text
Notebook 12.50
Pen 3.25
Folder 4.75
```

1. With Sage, ask **Read receipt.txt and add the three prices.** Expect a read-tool call and **20.50**.
2. With Swift, ask **Read receipt.txt. Which item is cheapest, and what is the difference between the highest and lowest price?** Expect **Pen**, **3.25**, and **9.25**.

Check the successful requests, requested ARC tier, served model, and charge in [Usage](/platform/usage). For Local, also inspect your gateway's request log. A correct answer alone does not prove the route. The client's cost display for a custom model is not the Rayline bill.

## Launcher availability

The launcher instructions below need Rayline **0.2.8 or later**. The latest public GitHub release was **0.2.7** when checked on 21 October 2026; the newer launchers were available in source. Do not assume `rayline update` supplies an unreleased version. The manual ARC tests above did not validate these launcher commands.


## Install

Install oh-my-pi from its [install docs](https://github.com/can1357/oh-my-pi#install). Use version 18.1.10 or later. Then sign in to Rayline:

```bash
rayline auth login
```

## Run

```bash
rayline omp
rayline --env <name> omp
```

Everything after `omp` goes to omp unchanged. See [launcher options](/rules-router/quickstart/other-agents#launcher-options).

## What Rayline writes

Rayline sets `PI_CODING_AGENT_DIR` to `~/.config/rayline/harness/omp/<env>/`:

| File | Contents | Rewritten each launch |
| --- | --- | --- |
| `models.yml` | A `rayline` provider in API-key mode using the Anthropic Messages API, pointed at Agent Gateway, with model `rayline-router` | Yes |
| `config.yml` | Assigns `rayline/rayline-router` to the `default`, `smol`, `slow`, and `plan` model roles | No; written once, then yours to edit |

Rayline removes `OMP_PROFILE` and `PI_PROFILE` from omp's environment, because a named profile would make omp ignore this directory. It also removes `CLAUDE_CONFIG_DIR`, so omp does not load another Claude Code configuration, for example when you start it from a `rayline claude` session.

## Key handling

`models.yml` names the `RAYLINE_KEY` environment variable instead of containing the key. The key is set only in omp's process environment and is never written to disk.

## Conversations

Each launch is one Agent Gateway conversation: the config sends a per-launch `x-conversation-id` header. Resuming in a new launch starts a new conversation.

From version 18.1.10, omp also sends its own session ID in API-key mode. When omp is older, Rayline prints a warning asking you to upgrade. On the production service the per-launch conversation ID still applies, so routing works either way.

## Manual setup (without the launcher)

Set `RAYLINE_KEY` and `RAYLINE_CONV_ID` first, as described in [manual setup](/rules-router/quickstart/other-agents#manual-setup-without-the-launcher).

Add this provider to `~/.omp/agent/models.yml`:

```yaml
providers:
  rayline:
    baseUrl: "https://api.rayline.ai"
    api: "anthropic-messages"
    auth: "apiKey"
    apiKey: "RAYLINE_KEY"
    headers:
      x-conversation-id: "RAYLINE_CONV_ID"
    models:
      - id: "rayline-router"
        name: "Rayline router"
        reasoning: true
        input: ["text", "image"]
        contextWindow: 200000
        maxTokens: 32000
```

To use it for every model role, add this to `~/.omp/agent/config.yml`:

```yaml
modelRoles:
  default: "rayline/rayline-router"
  smol: "rayline/rayline-router"
  slow: "rayline/rayline-router"
  plan: "rayline/rayline-router"
```

- In omp, `apiKey` and header values name environment variables. Write the variable's name, not `$RAYLINE_KEY`.
- `auth: "apiKey"` makes omp authenticate with the API key, as the launcher does. From omp 18.1.10 it also sends its own session ID in this mode.
- `baseUrl` has no `/v1`; omp adds the Messages path.

To keep this separate from your normal omp setup, put both files in another directory and set `PI_CODING_AGENT_DIR` to it, as the launcher does. Unset `OMP_PROFILE` and `PI_PROFILE` when you do, because a named profile makes omp ignore that variable.

Check it with a short prompt such as `Reply with the word ready.`

## Known limitations

- Named omp profiles are not used under `rayline omp`.
- Sessions run through Rayline are kept in Rayline's directory, separate from your normal omp sessions.
- Edits to `models.yml` are lost on the next launch. Change model roles in `config.yml`.

## Troubleshooting

- **`omp` not found on PATH.** Install oh-my-pi and check `which omp`.
- **Version warning at launch.** Upgrade omp to 18.1.10 or later.
- See also [shared troubleshooting](/rules-router/quickstart/other-agents#troubleshooting).
