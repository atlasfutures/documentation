Use **ARC Sage** for coding or **ARC Swift** for a faster, lower-cost tier. You can connect directly to Rayline without installing a gateway.

## Choose a connection

| Path | Request path | Inference |
| --- | --- | --- |
| Direct API | OpenCode → hosted Rayline | Cloud |
| Rayline Local gateway | OpenCode → your gateway → hosted Rayline | Cloud |

A local gateway does not imply on-device inference or locally running ARC. See [Hosted and Rayline Local](/tools/hosted-local).

## Install

Install [OpenCode](https://opencode.ai/docs/#install). Create a [Rayline API key](/platform/api-keys) and load it into `RAYLINE_KEY` in the shell where you will run the tool. Keep it out of project files.

## Connect directly

Use a separate configuration directory. These environment settings apply to the current shell:

```bash
mkdir -p "$HOME/.config/opencode-rayline"
export OPENCODE_CONFIG="$HOME/.config/opencode-rayline/opencode.json"
export RAYLINE_CONV_ID="$(uuidgen)"
```

Save this in `$OPENCODE_CONFIG`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "rayline/arc-sage",
  "small_model": "rayline/arc-swift",
  "provider": {
    "rayline": {
      "name": "Rayline",
      "npm": "@ai-sdk/anthropic",
      "options": {
        "baseURL": "https://api.rayline.ai/v1",
        "apiKey": "{env:RAYLINE_KEY}",
        "headers": { "x-conversation-id": "{env:RAYLINE_CONV_ID}" }
      },
      "models": {
        "arc-sage": { "name": "ARC Sage", "limit": { "context": 200000, "output": 2048 }, "reasoning": true, "tool_call": true },
        "arc-swift": { "name": "ARC Swift", "limit": { "context": 200000, "output": 2048 }, "reasoning": true, "tool_call": true }
      }
    }
  }
}
```

OpenCode expands `{env:NAME}` in keys and headers. Its `baseURL` **includes `/v1`**. `--standalone` is required with OpenCode 2 so the process uses your current configuration and environment. Project settings can still override `OPENCODE_CONFIG`. This smoke configuration allows a 2,048-token response; choose a larger supported output budget for longer coding tasks.

Start with Sage:

```bash
opencode --standalone --model rayline/arc-sage
```

For Swift, use `opencode --standalone --model rayline/arc-swift`. The provider prefix `rayline/`, where required by the tool, identifies your configured provider; the API IDs are `arc-sage` and `arc-swift`.

## Use a Rayline Local gateway

First [start a cloud-forwarding gateway](/tools/hosted-local#configure-a-cloud-forwarding-gateway). The gateway holds the upstream Rayline key. Keep the same provider configuration above and change:

| Setting | Direct production API | Gateway in the dev smoke |
| --- | --- | --- |
| `baseURL` | `https://api.rayline.ai/v1` | `http://127.0.0.1:23811/v1` |
| `RAYLINE_KEY` | Your Rayline API key | `local-client` for the test gateway |

Use your gateway’s actual port and authentication. **23811 is a test port**, not the default. The test gateway forwarded to `https://api-dev.rayline.ai`; direct tests used that dev host too. A successful dev test does not establish production availability.

## Verify the route

Create `receipt.txt`:

```text
Notebook 12.50
Pen 3.25
Folder 4.75
```

1. With Sage, ask **Read receipt.txt and add the three prices.** Expect a read-tool call and **20.50**.
2. With Swift, ask **Read receipt.txt. Which item is cheapest, and what is the difference between the highest and lowest price?** Expect **Pen**, **3.25**, and **9.25**.

In [Usage](/platform/usage), check successful requests, the requested ARC tier, the served model, and the charge. For Local, also inspect the gateway log. A correct answer alone does not prove the route.

## Launcher and session behavior

`rayline opencode` uses Agent Gateway’s `rayline-router` configuration. It does not select the ARC tiers in the manual configuration above. The launcher needs Rayline **0.2.8 or later**; 0.2.10 is available through the official installer. This launcher remains unverified by the manual-configuration smoke.

The launcher rewrites its `opencode.json` and supplies it through `OPENCODE_CONFIG`. OpenCode merges it with your global configuration; project settings take precedence. Use `--standalone` with the launcher too. See [launcher options](/rules-router/quickstart/other-agents#launcher-options).

Each launcher invocation generates a conversation ID. In manual setup, generate a new `RAYLINE_CONV_ID` for a new conversation; keep it when deliberately continuing the same one. The tool’s session ID and the gateway conversation ID are distinct.

## Troubleshooting

- **Another provider or model is used:** check project overrides and the active configuration directory.
- **Authentication fails:** check the key in the process environment and confirm whether the request is direct or going to your gateway.
- **You want your usual setup back:** open a fresh shell without these environment overrides. Your normal configuration has not been replaced.
- See [shared troubleshooting](/rules-router/quickstart/other-agents#troubleshooting).
