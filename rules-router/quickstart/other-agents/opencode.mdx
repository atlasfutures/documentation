Use **ARC Sage** (`arc-sage`) for coding, or **ARC Swift** (`arc-swift`) for a faster, lower-cost tier. You can connect directly to Rayline or send requests through a Rayline Local gateway. Both paths below use cloud inference.

<Note>
Live dev validation, **21 October 2026**: OpenCode **2.0.25** completed two file-reading tasks on each path, one with Sage and one with Swift. Local used an **unreleased Rayline 0.2.10 source build**. Production, launchers, resume, compaction, and extensions were not covered by these checks.
</Note>

## Choose a connection

| Path | Configuration | Gateway required? |
| --- | --- | --- |
| Direct API | Rayline's API base URL and your Rayline API key | No |
| Rayline Local | Your gateway's loopback URL and client authentication | Yes; the gateway holds the upstream Rayline key |

See [what “local” means](/tools/hosted-local). A local gateway does not imply on-device inference or locally running ARC.

## Use ARC directly

Use the [manual configuration below](#manual-setup-without-the-launcher), then replace `rayline-router` with `arc-sage` in the provider's model definition and default model settings. To make Swift available too, duplicate the model definition with ID `arc-swift` and name `ARC Swift`.

Set `model` to `rayline/arc-sage` and `small_model` to `rayline/arc-swift`. Run a specific tier with:

```bash
opencode --standalone --model rayline/arc-sage
opencode --standalone --model rayline/arc-swift
```

The `rayline/` prefix here identifies OpenCode's provider. The API model ID in the provider definition is bare `arc-sage` or `arc-swift`.

## Use a Rayline Local gateway

First configure a gateway that forwards `arc-sage` and `arc-swift` to your Rayline endpoint. Keep its upstream key in the gateway process environment. In this tool's manual provider configuration, change only:

| Setting | Direct production API | Local gateway used in the dev smoke |
| --- | --- | --- |
| `baseURL` | `https://api.rayline.ai/v1` | `http://127.0.0.1:23811/v1` |
| `RAYLINE_KEY` | Your Rayline API key | `local-client` for this test gateway |

The port and client authentication depend on your gateway. `23811` is a test port, not a Rayline default. Never send your real Rayline key to an unfamiliar local listener. The upstream dev endpoint used in validation was `https://api-dev.rayline.ai`.

## Verify your setup

Create a file named `receipt.txt` containing:

```text
Notebook 12.50
Pen 3.25
Folder 4.75
```

1. With Sage, ask **Read receipt.txt and add the three prices.** Expect a read-tool call and **20.50**.
2. With Swift, ask **Read receipt.txt. Which item is cheapest, and what is the difference between the highest and lowest price?** Expect **Pen**, **3.25**, and **9.25**.

Check the successful requests, requested ARC tier, served model, and charge in [Usage](/platform/usage). For Local, also inspect your gateway's request log. A correct answer alone does not prove the route. The client's cost display for a custom model is not the Rayline bill.

## Launcher availability

The launcher instructions below need Rayline **0.2.8 or later**. The latest public GitHub release was **0.2.7** when checked on 21 October 2026; the newer launchers were available in source. Do not assume `rayline update` supplies an unreleased version. The manual ARC tests above did not validate these launcher commands.


## Install

Install opencode from its [install docs](https://opencode.ai/docs/#install), then sign in to Rayline:

```bash
rayline auth login
```

## Run

```bash
rayline opencode --standalone
rayline opencode run --standalone "summarize this repo"
rayline --env <name> opencode --standalone
```

With opencode 2, pass `--standalone`. Without it, opencode sends the work to its shared background service, which does not see the config or key that Rayline sets for this launch. Everything after `opencode` goes to opencode unchanged. See [launcher options](/rules-router/quickstart/other-agents#launcher-options).

## What Rayline writes

| File | Contents | Rewritten each launch |
| --- | --- | --- |
| `~/.config/rayline/harness/opencode/<env>/opencode.json` | A `rayline` provider using opencode's Anthropic provider, pointed at Agent Gateway, with `rayline/rayline-router` as both `model` and `small_model` | Yes |

Rayline sets `OPENCODE_CONFIG` to this file. opencode merges it over your global config, so your other opencode settings still apply. Project-level opencode configs take precedence over it.

## Key handling

The config refers to the key as `{env:RAYLINE_KEY}`, opencode's environment substitution. The key itself is set only in opencode's process environment and is never written to disk.

## Conversations

Each launch is one Agent Gateway conversation: the config sends a per-launch `x-conversation-id` header. Continuing a session in a new launch with `opencode -c` or `--session` starts a new conversation.

## Manual setup (without the launcher)

Set `RAYLINE_KEY` and `RAYLINE_CONV_ID` first, as described in [manual setup](/rules-router/quickstart/other-agents#manual-setup-without-the-launcher).

Save this as `~/.config/opencode/opencode.json`, or merge its `provider` entry into your existing global or project config:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "rayline/rayline-router",
  "small_model": "rayline/rayline-router",
  "provider": {
    "rayline": {
      "name": "Rayline",
      "npm": "@ai-sdk/anthropic",
      "options": {
        "baseURL": "https://api.rayline.ai/v1",
        "apiKey": "{env:RAYLINE_KEY}",
        "headers": { "x-conversation-id": "{env:RAYLINE_CONV_ID}" }
      },
      "models": {
        "rayline-router": {
          "name": "Rayline router",
          "limit": { "context": 200000, "output": 32000 },
          "modalities": { "input": ["text", "image"], "output": ["text"] },
          "reasoning": true,
          "tool_call": true,
          "attachment": true
        }
      }
    }
  }
}
```

- `baseURL` includes `/v1`, because opencode's Anthropic provider adds only `/messages`.
- `{env:NAME}` is opencode's environment substitution, so neither the key nor the conversation ID is stored in the file.
- `small_model` sends opencode's background calls, such as session titles, through Agent Gateway too. Remove it to let opencode choose its own small model.
- The model `limit` tells opencode when to compact; keep it.

To keep this separate from your normal config, save it anywhere and set `OPENCODE_CONFIG` to its path, as the launcher does.

opencode 2 runs a shared background service, and the `opencode` command sends work to it. That service reads configuration and environment variables from the shell that first started it, so `RAYLINE_KEY`, `RAYLINE_CONV_ID`, and `OPENCODE_CONFIG` in your current shell do not reach it. Pass `--standalone` to run with a private server that uses your current shell:

```bash
opencode --standalone
opencode run --standalone "Reply with the word ready."
```

You should get a reply. Without `--standalone`, if the service was started without these variables, requests go out with no key, or through whatever model the service already uses.

## Known limitations

- With opencode 2, `rayline opencode` needs `--standalone`; see [Run](#run).
- A project-level opencode config that sets its own model or provider overrides Rayline's.
- Edits to Rayline's `opencode.json` are lost on the next launch. Put your own settings in opencode's global or project config.

## Troubleshooting

- **`opencode` not found on PATH.** Install opencode and check `which opencode`.
- **Requests never reach Agent Gateway, or use another model.** Add `--standalone`, so opencode does not hand the work to a background service started without Rayline's config.
- **Requests go to another provider.** Look for `model` or `provider` settings in the project's opencode config.
- See also [shared troubleshooting](/rules-router/quickstart/other-agents#troubleshooting).
