## Two ways to use ARC with pi

| Path | Request path | Inference |
| --- | --- | --- |
| Direct API | pi → hosted Rayline | Cloud |
| Rayline Local gateway | pi → your gateway → hosted Rayline | Cloud |

A local gateway does not imply on-device inference or locally running ARC. See [Hosted and Rayline Local](/tools/hosted-local).

## Install

Install [pi](https://github.com/earendil-works/pi#getting-started). Create a [Rayline API key](/platform/api-keys) and load it into `RAYLINE_API_KEY` in the shell where you will run the tool. Keep it out of project files.

## Connect directly

Use a separate configuration directory. These environment settings apply to the current shell:

```bash
export PI_CODING_AGENT_DIR="$HOME/.config/pi-rayline"
mkdir -p "$PI_CODING_AGENT_DIR"
export RAYLINE_CONV_ID="$(uuidgen)"
```

Save this in `$PI_CODING_AGENT_DIR/models.json`:

```json
{
  "providers": {
    "rayline": {
      "baseUrl": "https://api.rayline.ai",
      "api": "anthropic-messages",
      "apiKey": "$RAYLINE_API_KEY",
      "headers": { "x-conversation-id": "$RAYLINE_CONV_ID" },
      "compat": { "sendSessionAffinityHeaders": true },
      "models": [
        { "id": "arc-sage-1.0", "name": "ARC Sage", "reasoning": false, "input": ["text"], "contextWindow": 200000, "maxTokens": 2048 },
        { "id": "arc-swift-1.0", "name": "ARC Swift", "reasoning": false, "input": ["text"], "contextWindow": 200000, "maxTokens": 2048 }
      ]
    }
  }
}
```

pi expands `$NAME` in keys and headers. Its `baseUrl` has **no `/v1`**. The optional session-affinity setting sends pi’s session ID alongside the conversation header. This configuration allows a 2,048-token response; choose a larger supported output budget for longer coding tasks.

Start with Sage:

```bash
pi --provider rayline --model arc-sage-1.0
```

For Swift, use `pi --provider rayline --model arc-swift-1.0`. The provider prefix `rayline/`, where required by the tool, identifies your configured provider; the API IDs are `arc-sage-1.0` and `arc-swift-1.0`.

## Use a Rayline Local gateway

First [start a cloud-forwarding gateway](/tools/hosted-local#configure-a-cloud-forwarding-gateway). The gateway holds the upstream Rayline key. Keep the same provider configuration above and change:

| Setting | Rayline platform | Rayline Local |
| --- | --- | --- |
| `baseUrl` | `https://api.rayline.ai` | `http://127.0.0.1:23811` |
| `RAYLINE_API_KEY` | Your Rayline API key | `local-client` for the gateway below |

Use the port configured for your gateway. The linked setup uses port **23811** and keeps your Rayline key in the gateway process.

## Launcher and session behavior

`rayline pi` uses Agent Gateway’s `rayline-router` configuration. It does not select the ARC tiers in the manual configuration above. The launcher needs Rayline **0.2.8 or later**; 0.2.10 is available through the official installer.

The launcher rewrites `models.json` and creates `settings.json` once. It keeps auth and sessions in its own directory. See [launcher options](/rules-router/quickstart/other-agents#launcher-options).

Each launcher invocation generates a conversation ID. In manual setup, generate a new `RAYLINE_CONV_ID` for a new conversation; keep it when deliberately continuing the same one. The tool’s session ID and the gateway conversation ID are distinct.

## Troubleshooting

- **Another provider or model is used:** check project overrides and the active configuration directory.
- **Authentication fails:** check the key in the process environment and confirm whether the request is direct or going to your gateway.
- **You want your usual setup back:** open a fresh shell without these environment overrides. Your normal configuration has not been replaced.
- See [shared troubleshooting](/rules-router/quickstart/other-agents#troubleshooting).

## Configurable ARC

To use configurable ARC, add a model entry named `arc-1.0` alongside the Sage and Swift
entries above, then select it with `--model arc-1.0`.
For Local, include `arc-1.0` in the gateway endpoint’s model list as well.

Configurable ARC uses the served model’s catalog price rather than a fixed tier
rate; see [Configure ARC routing](/arc/gateway-routing).

### Send your own routing value

pi 0.80.2 supports a `before_provider_request` extension hook. Save this as
`arc-routing.ts`:

```typescript
export default function (pi) {
  pi.on("before_provider_request", (event, ctx) => {
    if (ctx.model?.provider !== "rayline" || ctx.model?.id !== "arc-1.0") return;
    const value = Number(process.env.RAYLINE_VALUE_USD);
    if (!Number.isFinite(value) || value < 0.1 || value > 5) {
      throw new Error("RAYLINE_VALUE_USD must be between 0.1 and 5");
    }
    return { ...event.payload, routing: { value_usd: value, temperature: 0 } };
  });
  pi.on("after_provider_response", (event) => {
    console.error("ARC routing:", event.headers["x-rayline-routing"] ?? "not exposed");
  });
}
```

Start pi with the extension explicitly loaded:

```bash
RAYLINE_VALUE_USD=0.5 pi --extension ./arc-routing.ts --provider rayline --model arc-1.0
```

The guard leaves other providers and ARC tiers unchanged. This routing
`temperature` controls ARC exploration, not the answer model’s temperature.
Check the response echo rather than assuming the setting took effect.

The `x-rayline-routing` response header reports whether each setting was applied. A workspace privacy policy can override exploration settings; check `status` and `reason` in that header.
