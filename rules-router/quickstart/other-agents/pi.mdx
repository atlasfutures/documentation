Use **ARC Sage** (`arc-sage`) for coding, or **ARC Swift** (`arc-swift`) for a faster, lower-cost tier. You can connect directly to Rayline or send requests through a Rayline Local gateway. Both paths below use cloud inference.

<Note>
Live dev validation, **21 October 2026**: pi **0.80.2** completed two file-reading tasks on each path, one with Sage and one with Swift. Local used an **unreleased Rayline 0.2.10 source build**. Production, launchers, resume, compaction, and extensions were not covered by these checks.
</Note>

## Choose a connection

| Path | Configuration | Gateway required? |
| --- | --- | --- |
| Direct API | Rayline's API base URL and your Rayline API key | No |
| Rayline Local | Your gateway's loopback URL and client authentication | Yes; the gateway holds the upstream Rayline key |

See [what “local” means](/tools/hosted-local). A local gateway does not imply on-device inference or locally running ARC.

## Use ARC directly

Use the [manual configuration below](#manual-setup-without-the-launcher), then replace `rayline-router` with `arc-sage` in the provider's model definition and default model settings. To make Swift available too, duplicate the model definition with ID `arc-swift` and name `ARC Swift`.

Run a specific tier with:

```bash
pi --provider rayline --model arc-sage
pi --provider rayline --model arc-swift
```

## Use a Rayline Local gateway

First configure a gateway that forwards `arc-sage` and `arc-swift` to your Rayline endpoint. Keep its upstream key in the gateway process environment. In this tool's manual provider configuration, change only:

| Setting | Direct production API | Local gateway used in the dev smoke |
| --- | --- | --- |
| `baseUrl` | `https://api.rayline.ai` | `http://127.0.0.1:23811` |
| `RAYLINE_KEY` | Your Rayline API key | `local-client` for this test gateway |

The port and client authentication depend on your gateway. `23811` is a test port, not a Rayline default. Never send your real Rayline key to an unfamiliar local listener. The upstream dev endpoint used in validation was `https://api-dev.rayline.ai`.

## Verify your setup

Create a file named `receipt.txt` containing:

```text
Notebook 12.50
Pen 3.25
Folder 4.75
```

1. With Sage, ask **Read receipt.txt and add the three prices.** Expect a read-tool call and **20.50**.
2. With Swift, ask **Read receipt.txt. Which item is cheapest, and what is the difference between the highest and lowest price?** Expect **Pen**, **3.25**, and **9.25**.

Check the successful requests, requested ARC tier, served model, and charge in [Usage](/platform/usage). For Local, also inspect your gateway's request log. A correct answer alone does not prove the route. The client's cost display for a custom model is not the Rayline bill.

## Launcher availability

The launcher instructions below need Rayline **0.2.8 or later**. The latest public GitHub release was **0.2.7** when checked on 21 October 2026; the newer launchers were available in source. Do not assume `rayline update` supplies an unreleased version. The manual ARC tests above did not validate these launcher commands.


## Install

Install pi (`@earendil-works/pi-coding-agent`) from its [install docs](https://github.com/earendil-works/pi#getting-started), then sign in to Rayline:

```bash
rayline auth login
```

## Run

```bash
rayline pi
rayline pi -p "summarize this repo"
rayline --env <name> pi
```

Everything after `pi` goes to pi unchanged. See [launcher options](/rules-router/quickstart/other-agents#launcher-options).

## What Rayline writes

Rayline sets `PI_CODING_AGENT_DIR` to `~/.config/rayline/harness/pi/<env>/`:

| File | Contents | Rewritten each launch |
| --- | --- | --- |
| `models.json` | A `rayline` provider using the Anthropic Messages API, pointed at Agent Gateway, with model `rayline-router` | Yes |
| `settings.json` | Makes `rayline` and `rayline-router` the defaults | No; written once, then yours to edit |

pi also keeps its own auth and sessions in that directory, so sessions run through Rayline are separate from your normal pi sessions.

## Key handling

`models.json` refers to the key as `$RAYLINE_KEY`, which pi resolves from its environment. The key is set only in pi's process environment and is never written to disk.

## Conversations

Each launch is one Agent Gateway conversation: the config sends a per-launch `x-conversation-id` header. Rayline also turns on pi's session-affinity header. Resuming with `-c` or `--resume` in a new launch starts a new conversation.

## Manual setup (without the launcher)

Set `RAYLINE_KEY` and `RAYLINE_CONV_ID` first, as described in [manual setup](/rules-router/quickstart/other-agents#manual-setup-without-the-launcher).

Add this provider to `~/.pi/agent/models.json`, merging it into `providers` if the file exists:

```json
{
  "providers": {
    "rayline": {
      "baseUrl": "https://api.rayline.ai",
      "api": "anthropic-messages",
      "apiKey": "$RAYLINE_KEY",
      "headers": { "x-conversation-id": "$RAYLINE_CONV_ID" },
      "compat": { "sendSessionAffinityHeaders": true },
      "models": [
        {
          "id": "rayline-router",
          "name": "Rayline router",
          "reasoning": true,
          "input": ["text", "image"],
          "contextWindow": 200000,
          "maxTokens": 32000
        }
      ]
    }
  }
}
```

To make it the default, add these keys to `~/.pi/agent/settings.json`:

```json
{ "defaultProvider": "rayline", "defaultModel": "rayline-router" }
```

- `baseUrl` has no `/v1`; pi adds the Messages path.
- pi expands `$NAME` in `apiKey` and header values from its environment.
- `compat.sendSessionAffinityHeaders` makes pi send its own session ID as well. The launcher sets it, but the hosted service currently keys conversations on `x-conversation-id`, so it is optional.
- The launcher does not set `compat.allowEmptySignature` for the hosted service. Leave it unset.

To keep this separate from your normal pi setup, put both files in another directory and set `PI_CODING_AGENT_DIR` to it, as the launcher does. pi then keeps that setup's sessions and login there too.

Use the two file-reading checks above to verify tool execution.

## Known limitations

- Sessions from your normal pi setup are not visible under `rayline pi`, and the reverse.
- Edits to `models.json` are lost on the next launch. Change defaults in `settings.json`.

## Troubleshooting

- **`pi` not found on PATH.** Install pi and check `which pi`.
- **pi does not pick the Rayline model.** Check `settings.json` in the config directory; delete it to have Rayline write the defaults again on the next launch.
- See also [shared troubleshooting](/rules-router/quickstart/other-agents#troubleshooting).
