[Unreal Agent](https://github.com/unreallabsai/unreal-agent) can call Rayline's
Responses API directly. It does not require Rayline Local for this path.

<Note>
The official **0.3.1** macOS arm64 runner passed two real file-tool tasks against
the **development API** on 21 October 2026: one with ARC Sage and one with ARC
Swift. Both executed `cat receipt.txt` successfully and returned the correct
answer. Production and the interactive TUI remain unverified.
</Note>

## Direct API

Install the official runner:

```bash
brew install unreallabsai/tap/unreal-agent
```

Load your Rayline key into `UNREAL_HARNESS_LLM_API_KEY` from your secrets manager;
see [API keys](/platform/api-keys). Then configure the Responses provider:

```bash
export UNREAL_HARNESS_LLM_PROVIDER=openai
export UNREAL_HARNESS_LLM_BASE_URL=https://api.rayline.ai/v1
export UNREAL_HARNESS_LLM_MODEL=arc-sage
```

The production URL above is the intended configuration. The recorded smoke used
`https://api-dev.rayline.ai/v1` with a development key.

Run the agent from a project directory:

```bash
unreal-agent-runner -workspace "$PWD" -p 'Read receipt.txt and calculate the total. Do not change files.'
```

The runner writes JSONL events to stdout. The `openai` provider selects the
Responses wire protocol; it does not mean the request is billed by OpenAI.

## Verify both tiers

Create `receipt.txt` with known prices. Run one fresh task asking Sage for the
total. Then select Swift and ask for the cheapest item and price spread:

```bash
UNREAL_HARNESS_LLM_MODEL=arc-swift unreal-agent-runner \
  -workspace "$PWD" \
  -p 'Read receipt.txt. Which item is cheapest, and what is the price spread? Do not change files.'
```

Check for a completed shell operation with exit code zero **and** a final answer
that matches the file. An exit-zero runner process alone is insufficient.
Inspect [Rayline Usage](/platform/usage) for the corresponding requests.

## Rayline Local

Use the **Anthropic provider** for the tested Local path. Start a
[gateway forwarding to hosted Rayline](/tools/hosted-local#configure-a-cloud-forwarding-gateway),
then set:

```bash
export UNREAL_HARNESS_LLM_PROVIDER=anthropic
export UNREAL_HARNESS_LLM_BASE_URL=http://127.0.0.1:23811/v1
export UNREAL_HARNESS_LLM_API_KEY=local-client
export UNREAL_HARNESS_LLM_MODEL=arc-sage
```

Use your gateway's actual port and authentication. The placeholder above is for
the isolated test gateway; its environment holds the real upstream key. Unreal's
Anthropic provider expects `/v1` here. This path forwards cloud inference; it
does not run the inference model or ARC locally.

On 21 October 2026, after the dev gateway fix, both Sage and Swift completed
real `cat receipt.txt` calls and returned the correct answers through this
Messages path. The same provider also completed both tasks directly against
`https://api-dev.rayline.ai/v1`. The direct Sage run executed an extra arithmetic
command despite the prompt's restriction; these tests establish transport and
tool execution, not instruction-following guarantees.

<Warning>
The **OpenAI/Responses provider through Local 0.2.10** remains blocked: both
Sage and Swift exited zero with no tool call and an empty answer. A fix is pending
release. Use the tested Anthropic path above, or the direct Responses path.
The earlier Anthropic invalid-request failure was fixed on dev; production
verification is still pending.
</Warning>
