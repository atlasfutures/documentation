## Check the client path

Confirm whether the client uses hosted routing, a subscription passthrough, or a local provider. Follow its [quickstart](/rules-router/quickstart) again if the wiring is unclear.

For hosted routing, check `rayline auth status`. For a manually configured client, verify its base URL and workspace API key are from the same environment. Do not print the key.

## Check the runtime

```bash
rayline router status
rayline router logs --lines 120
```

If a client points to a stopped local runtime, relaunch through `rayline claude` or `rayline codex` with the intended configuration. Do not stop shared runtime processes while another session needs them.

## Certificate errors

Transparent proxy mode creates a local certificate authority and passes it to Claude Code through `NODE_EXTRA_CA_CERTS`. The certificate is `proxy-ca.pem` in:

| OS | Directory |
| --- | --- |
| macOS | `~/Library/Application Support/rayline` |
| Linux | `$XDG_CONFIG_HOME/rayline`, or `~/.config/rayline` |
| Windows | `%APPDATA%\rayline` |

An Anthropic SDK client that you point at the proxy yourself must trust this file; see [Rayline for agents](/rules-router/quickstart/agents). Do not fix TLS failures by disabling certificate verification. If your organization runs its own HTTPS proxy, pass its CA bundle with `rayline claude --upstream-ca-path <path>`. Hosted Claude Code sessions can avoid the proxy with `--via env`.

## Port conflicts

The local runtime uses ports 20808 to 20814 on `127.0.0.1`; the [CLI reference](/rules-router/cli#ports) lists each one. If another program holds a port, check what is listening, then either stop that program or move Rayline:

```bash
lsof -nP -iTCP:20810 -sTCP:LISTEN
RAYLINE_PROXY_PORT=20910 rayline claude
```

`rayline claude --isolated` runs its own proxy on port 20812, so it does not compete with the shared proxy on 20810.

## Provider errors

A reachable router does not guarantee that a provider is healthy, your model assignment is available, or your local model fits in memory. Inspect the selected endpoint, model, and sanitized provider error.

Retries and fallbacks depend on the route and failure. There is no guarantee that every failure can be recovered automatically.
