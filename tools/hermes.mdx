<span id="verify-the-route" />

Use **ARC Sage** (`arc-sage-1.0`) for challenging coding and agent tasks, or **ARC Swift** (`arc-swift-1.0`) as a fast workhorse for everyday tasks. Connect to the Rayline Platform with the configuration below.

Install the tool using its [installation guide](https://hermes-agent.nousresearch.com/docs/getting-started/installation) before you begin.

<span id="use-arc-directly" />

<span id="manual-setup-without-the-launcher" />

## Connect to the Rayline Platform

Set `RAYLINE_API_KEY` first, as described in [manual setup](/tools/more-tools#manual-setup-without-the-launcher).

Add these providers to `~/.hermes/config.yaml`, and point `model` at the first one:

```yaml
model:
  provider: "custom:rayline-anth"
  default: "arc-sage-1.0"
  context_length: 200000
providers:
  rayline-anth:
    api_mode: "anthropic_messages"
    base_url: "https://api.rayline.ai"
    key_env: "RAYLINE_API_KEY"
    models:
      arc-sage-1.0:
        context_length: 200000
  rayline-resp:
    api_mode: "codex_responses"
    base_url: "https://api.rayline.ai/v1"
    key_env: "RAYLINE_API_KEY"
    models:
      arc-sage-1.0:
        context_length: 200000
```

- `key_env` names the variable that holds the key; Hermes expands `${NAME}` in other values.
- `rayline-anth` uses the Messages API at `/v1/messages`, so its `base_url` has no `/v1`. `rayline-resp` uses the Responses API at `/v1/responses`, so its `base_url` ends in `/v1`. Use `rayline-resp` with ARC only in an environment that [advertises Responses support](/arc/availability#check-protocol-support), and set its base URL to that environment. Otherwise, use `rayline-anth` for ARC Sage and ARC Swift.
- The launcher also sets `fallback_providers: []`, so a failed request is not retried against another provider. Add it if you want the same behaviour.

To keep this separate from your normal Hermes home, save it as `config.yaml` in another directory and set `HERMES_HOME` to that directory, as the launcher does.

Check it with `hermes -z "Reply with the word ready."`.

<span id="use-a-rayline-local-gateway" />

## Use a Raydock gateway

Configure the [cloud-forwarding gateway](/raydock/connections#configure-a-cloud-forwarding-gateway) with `"protocol": "anthropic_messages"` and `"base_url": "https://api.rayline.ai"`, then start it. In the Hermes Messages provider configuration, replace the base URL with your gateway’s URL, without `/v1`. Use `http://127.0.0.1:23811` for the linked gateway setup and `RAYLINE_API_KEY=local-client` in the client. The gateway holds your Rayline API key.

## Try your first task

From your project directory, run:

```bash
hermes --provider rayline-anth --model arc-sage-1.0 -z "Read the README and explain how to run this project."
```

To use Swift, add `arc-swift-1.0` to the provider’s models using the same settings as Sage, then select it in your command. View requests and the model ARC selected in [Rayline Usage](/platform/usage).

## Launcher availability

The launcher instructions below require version 0.2.12 or later. Install the current version from the [Raydock install guide](/raydock/cli#install).

## Install

Install Hermes Agent from its [install docs](https://hermes-agent.nousresearch.com/docs/getting-started/installation). Use v2026.9.21 or later. Then sign in to Rayline:

```bash
raydock auth login
```

## Run

```bash
raydock hermes
raydock hermes --provider rayline-resp
raydock hermes --model rayline-router
raydock --env <name> hermes
```

Everything after `hermes` goes to Hermes unchanged. See [launcher options](/tools/more-tools#launcher-options).

<span id="what-rayline-writes" />

## What Raydock writes

Raydock sets `HERMES_HOME` to `~/.config/rayline/harness/hermes/<env>/` and writes `config.yaml` there on every launch. From Raydock 0.3.0, the main model is ARC Sage. It defines two providers, each listing `arc-sage-1.0`, `arc-swift-1.0`, and `rayline-router`:

| Provider | API | Use |
| --- | --- | --- |
| `rayline-anth` | Anthropic Messages | The default |
| `rayline-resp` | OpenAI Responses | Select with `--provider rayline-resp` |

To use Legacy Rules Router, pass `--model rayline-router`. Raydock rewrites `config.yaml` on every launch, so choose Legacy on each run. You can also use the manual configuration above with model `rayline-router`.

Fallback providers are turned off, so a failed request is not retried against another provider. Hermes keeps its sessions, memories, and skills in `HERMES_HOME`, so they are separate from your normal Hermes setup.

## Key handling

The launcher writes the key as each provider's `api_key` in the Raydock-owned `config.yaml`, readable only by you, and removes it from Hermes' environment. A manual config names the variable instead, with `key_env: RAYLINE_API_KEY`.

## Conversations

Each launch is one Rayline conversation; the launcher sends a per-launch conversation ID. Hermes v2026.9.21 or later is needed for that launcher-supplied header on Messages.

Manual Messages connections send no session identifier. Rayline derives the conversation from the opening messages, both directly and through the gateway. Separate sessions with identical openings can be grouped together; see [conversation grouping](/tools/more-tools#the-conversation-id).

## Known limitations

- Sessions, memories, and skills from your normal Hermes home are not available under `raydock hermes`.
- Edits to Rayline's `config.yaml` are lost on the next launch.

## Troubleshooting

- **`hermes` not found on PATH.** Install Hermes Agent and check `which hermes`.
- **The launcher's conversation ID is ignored.** Upgrade to Hermes v2026.9.21 or later so its Messages provider accepts the launcher-supplied header.
- See also [shared troubleshooting](/tools/more-tools#troubleshooting).
