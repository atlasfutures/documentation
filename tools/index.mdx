Rayline connects the coding agent you already use to models. Pick what decides the model for each request, then follow the guide for your tool.

- **ARC** chooses the model and reasoning effort for every request. Coding tools use **ARC Sage** (`arc-sage`) by default, or **ARC Swift** (`arc-swift`) for lower cost. See [Swift and Sage](/arc/models).
- **Your routing rules** pin the main agent and assign models to subagents. See [routing policies](/rules-router/policies).

## Before you start

1. Install the [Rayline CLI](/rules-router/cli#install) and sign in with `rayline auth login`. The CLI creates a router key for the selected workspace; see [API keys](/platform/api-keys) to use a workspace key instead.
2. Decide where the requests go. [Hosted and Rayline Local](/tools/hosted-local) explains which requests leave your machine and how each path is billed.
3. Check the request in [usage](/platform/usage) after your first task: the requested model, the model that served it, and the charge.

## Other agents and apps

Agent Gateway and ARC are not restricted to coding agents. Before connecting another client, check its request protocol, authentication, model identifiers, and required features against [tool compatibility](/rules-router/reference) and [API compatibility](/arc/reference/compatibility). A configurable API base URL alone does not guarantee compatibility. To build your own agent, see [custom agents and SDKs](/rules-router/quickstart/agents).
