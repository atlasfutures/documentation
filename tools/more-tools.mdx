## Use ARC with your agent harness

Follow your tool’s guide to connect to the Rayline Platform. Each guide also explains its Raydock option. Both paths can use cloud inference; see [Rayline Platform and Raydock](/raydock/connections).

## Raydock launchers

From Raydock 0.3.0, the launchers below run on ARC by default; see [Which model runs](#which-model-runs). [Legacy Rules Router](/legacy/rules-router) is used only when you choose it. Install the agent first; Raydock configures the route but does not bundle the agent.

| Command | Agent | Install | Guide |
| --- | --- | --- | --- |
| `raydock opencode` | [opencode](https://opencode.ai) | [opencode install docs](https://opencode.ai/docs/#install) | [opencode](/tools/opencode) |
| `raydock pi` | [pi](https://pi.dev) | [pi install docs](https://github.com/earendil-works/pi#getting-started) | [pi](/tools/pi) |
| `raydock omp` | [oh-my-pi](https://omp.sh) | [oh-my-pi install docs](https://github.com/can1357/oh-my-pi#install) | [oh-my-pi](/tools/omp) |
| `raydock hermes` | [Hermes Agent](https://hermes-agent.nousresearch.com) | [Hermes Agent install docs](https://hermes-agent.nousresearch.com/docs/getting-started/installation) | [Hermes Agent](/tools/hermes) |
| `raydock openclaw` | [OpenClaw](https://openclaw.ai) | [OpenClaw install docs](https://docs.openclaw.ai/install) | [OpenClaw](/tools/openclaw) |

```bash
raydock auth login
raydock pi
raydock opencode run --standalone "summarize this repo"
```

## Launcher options

Everything after the agent's name goes to the agent unchanged, including `--help`. Raydock reads only two options, and only when they come directly after the agent's name, before any of the agent's own arguments:

| Option | Purpose |
| --- | --- |
| `--env <name>` | Use another [hosted environment](/raydock/cli#hosted-environment). You can also put it before the agent's name. |
| `--auth-token <token>` | Use this account token instead of your stored sign-in. |

Use `--` to pass an argument that would otherwise be read as a Raydock option.

## What the launcher does

1. Signs you in and creates a router key if you have none, as `raydock claude` does. In a non-interactive shell, run `raydock auth login` first.
2. Writes a Raydock config for the agent to `~/.config/rayline/harness/<agent>/<env>/`, readable only by you on macOS and Linux, and points the agent at it through the agent's own config variable. Your normal configuration for that agent is not changed.
3. Starts the agent on ARC over the Anthropic Messages API, so ARC chooses the model and reasoning effort for each request; see [Which model runs](#which-model-runs). The agent is told the model has a 200,000-token context window and up to 32,000 output tokens.

Each launch prints the router URL, the conversation ID, and the config directory. Raydock rewrites the files it owns on every launch, so edit the agent's settings through its own files, not Raydock's; each agent's guide lists which files those are.

## How your key is handled

Since Rayline 0.2.12, the launcher writes the router key only into the Raydock-owned config directory, readable only by you, and removes `RAYLINE_KEY` and `RAYLINE_ROUTER_API_KEY` from the agent's environment, so the agent's tools never see the key. Each agent's guide says how its config refers to the key. To use a specific workspace key instead of the stored one, export `RAYLINE_ROUTER_API_KEY` before launching.

## Conversations

Rayline groups requests into conversations. From Raydock 0.3.0 the launchers do not send a conversation ID of their own: Rayline keys each conversation on the session identifier the agent sends, so resuming a session in a new launch keeps its conversation. Where an agent sends no session identifier, Rayline derives one from the opening messages. Each agent's guide says which applies.

## Manual setup (without the launcher)

Each tool’s guide includes a manual ARC configuration. Those configurations read your key from `RAYLINE_API_KEY`; the launcher instead keeps it in its own config files.

For an existing Legacy Rules Router integration, the Kilo, OpenCode, pi, omp and Hermes Messages configurations can use `rayline-router` instead of an ARC model ID. OpenClaw needs the [Messages provider settings](/tools/openclaw#connect-to-the-rayline-platform) described in its guide. Chat Completions does not serve Legacy Rules Router. Through Raydock, use an `anthropic_messages` upstream and include `rayline-router` in its model list; see [gateway configuration](/raydock/connections#configure-a-cloud-forwarding-gateway).

### The API key

Create a key in **API Keys** on the [Rayline Platform](https://platform.rayline.ai/keys); see [API keys](/platform/api-keys). Export it as `RAYLINE_API_KEY` in the shell that starts the agent, for example from your secrets manager:

```bash
export RAYLINE_API_KEY="<your Rayline API key>"
```

Every config below refers to `RAYLINE_API_KEY` by name, using the agent's own environment-variable syntax, so the key is never written into a config file. Do not paste the key into the config itself.

### The conversation ID

Rayline recognises the native session identifiers sent by OpenCode, pi, omp and
OpenClaw's Chat Completions provider with their documented settings, under the
launcher and in manual direct connections alike. Hermes sends one only when its
provider entry sets `session_affinity_header`; without it, Hermes on Messages
sends no session identifier and Rayline derives a conversation from the opening
messages. The launcher does not set that option.

The Raydock gateway does not forward session-affinity headers. A Messages
upstream preserves session metadata in the body, such as omp's `metadata.user_id`.
When no session identifier reaches Rayline, it groups requests by their opening
messages. Separate sessions with identical openings can be grouped together.
Use the direct connection when you need the harness's session headers to reach
Rayline. You do not need to generate a conversation ID by hand for these setups.

Requests in one conversation are routed together, pinned to the same provider
backend where supported to help prompt-cache reuse, and grouped in usage.

### Check the connection

After setting up an agent, send a short prompt such as `Reply with the word ready.` You should get a reply, and the request should appear with its selected model in [Inspect routed requests](/platform/usage). An authentication error usually means `RAYLINE_API_KEY` is missing from the agent's environment or holds the wrong key.

## Troubleshooting

- **`<agent>` not found on PATH.** Install the agent and make sure its binary is on your `PATH`; the error includes an install hint. On Windows, Rayline also finds `.exe`, `.cmd`, `.bat`, and `.com` files.
- **Sign-in errors in scripts.** Run `raydock auth login` once on a terminal, then check `raydock status`.
- **The agent uses another model.** Check whether a project-level config for that agent overrides the provider or model.

## Which model runs

Each launcher gives the main agent ARC Sage (`arc-sage-1.0`). Where the agent has a separate setting for small or background work, that setting gets ARC Swift (`arc-swift-1.0`). Every generated config also lists Legacy Rules Router (`rayline-router`), so you can choose it with the agent's own model flag or picker:

| Launcher | ARC Sage | ARC Swift | Use Legacy Rules Router |
| --- | --- | --- | --- |
| `raydock opencode` | `model` | `small_model` | `-m rayline/rayline-router` |
| `raydock pi` | Main model | Not used | `--model rayline/rayline-router`, or pi's model picker |
| `raydock omp` | `default`, `slow`, and `plan` roles | `smol` role | Choose `rayline/rayline-router` for a role |
| `raydock hermes` | Main model | Not used | `--model rayline-router`, for that run |
| `raydock openclaw` | Main model | Not used | Switch the session's model to `rayline/rayline-router`, for that run |

A model you pick in pi or omp is saved and kept on later launches. Raydock rewrites the model settings in its Hermes and OpenClaw configs on every launch, so choose Legacy there on each run. For Claude Code and Codex, see [raydock claude](/raydock/cli/claude) and [Codex](/tools/codex#choose-who-serves-the-requests).

You can also follow an agent's manual setup and request `rayline-router` instead of an ARC model ID, as described in [Manual setup](#manual-setup-without-the-launcher). Check [usage](/platform/usage) after your first task.
