## Two ways to use ARC with OpenCode

| Path | Request path | Inference |
| --- | --- | --- |
| Direct API | OpenCode → Rayline Platform | Cloud |
| Raydock gateway | OpenCode → your gateway → Rayline Platform | Cloud |

Both reach the same hosted ARC. Start with **Direct**, the simpler setup. Use **Raydock** when you want Rayline's local features: routing rules, provider configuration, or an on-device model. See [Rayline Platform and Raydock](/raydock/connections) for what each path gives you.

A local gateway does not imply on-device inference or locally running ARC. See [Rayline Platform and Raydock](/raydock/connections).

## Install

Install [OpenCode](https://opencode.ai/docs/#install). Create a [Rayline API key](/platform/api-keys) and load it into `RAYLINE_API_KEY` in the shell where you will run the tool. Keep it out of project files.

## Connect directly

This path reads your key from `RAYLINE_API_KEY`, set in the [Install](#install) step. Use a separate configuration directory. These environment settings apply to the current shell:

```bash
mkdir -p "$HOME/.config/opencode-rayline"
export OPENCODE_CONFIG="$HOME/.config/opencode-rayline/opencode.json"
```

Save this in `$OPENCODE_CONFIG`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "rayline/arc-sage-1.0",
  "small_model": "rayline/arc-swift-1.0",
  "provider": {
    "rayline": {
      "name": "Rayline",
      "npm": "@ai-sdk/anthropic",
      "options": {
        "baseURL": "https://api.rayline.ai/v1",
        "apiKey": "{env:RAYLINE_API_KEY}"
      },
      "models": {
        "arc-sage-1.0": {
          "name": "ARC Sage",
          "limit": { "context": 200000, "output": 128000 },
          "cost": { "input": 1, "output": 5, "cache_read": 0.05, "cache_write": 1.25 },
          "reasoning": true,
          "tool_call": true
        },
        "arc-swift-1.0": {
          "name": "ARC Swift",
          "limit": { "context": 200000, "output": 128000 },
          "cost": { "input": 0.05, "output": 0.25, "cache_read": 0.005, "cache_write": 0.0625 },
          "reasoning": true,
          "tool_call": true
        }
      }
    }
  }
}
```

OpenCode expands `{env:NAME}` in keys and headers. Its `baseURL` **includes `/v1`**. `--standalone` is required with OpenCode 2 so the process uses your current configuration and environment. Project settings can still override `OPENCODE_CONFIG`. The configuration allows responses of up to 128,000 tokens, the maximum ARC accepts.

`cost` gives OpenCode each tier's fixed rate card, in US dollars per million tokens, so its session cost display matches what Rayline bills. The rates come from [ARC pricing](/arc/pricing); update them if the card changes.

Start with Sage:

```bash
opencode --standalone --model rayline/arc-sage-1.0
```

For Swift, use `opencode --standalone --model rayline/arc-swift-1.0`. The provider prefix `rayline/`, where required by the tool, identifies your configured provider; the API IDs are `arc-sage-1.0` and `arc-swift-1.0`.

For a scripted, non-interactive run, use `opencode run` and close standard input, or the run waits for input that never arrives:

```bash
opencode run --standalone --model rayline/arc-sage-1.0 "Reply with the word ready." < /dev/null
```

## Choose ARC in the web interface

After adding the provider configuration, open **Settings → Models**, search for `arc-`, and enable **arc-sage-1.0** and **arc-swift-1.0**. This makes both models available in the session picker.

![Enable ARC Sage and ARC Swift in OpenCode Settings → Models](/images/tools/setup/opencode-model-settings.webp)

Start a new session and open the model picker below the prompt. Choose **arc-sage-1.0** for challenging tasks or **arc-swift-1.0** for everyday work.

![Choose ARC Sage or ARC Swift in the OpenCode session model picker](/images/tools/setup/opencode-model-picker.webp)

## Use a Raydock gateway

Configure the [cloud-forwarding gateway](/raydock/connections#configure-a-cloud-forwarding-gateway) with `"protocol": "anthropic_messages"` and `"base_url": "https://api.rayline.ai"`, then start it; that is where your real Rayline key now lives. Keep the OpenCode provider configuration above unchanged. Only two client settings differ from the direct setup:

| Setting | Direct | Raydock |
| --- | --- | --- |
| `baseURL` | `https://api.rayline.ai/v1` | `http://127.0.0.1:23811/v1` |
| `RAYLINE_API_KEY` | Your Rayline API key | `local-client` |

`23811` is the port the linked gateway setup uses; if you started yours on a different port, use that one.

## Launcher and session behavior

From Raydock **0.3.0**, `raydock opencode` runs on ARC: `model` is ARC Sage and `small_model` is ARC Swift. To use Legacy Rules Router, pass `-m rayline/rayline-router` to the launcher, or use the manual configuration above with model `rayline-router`.

The launcher rewrites its `opencode.json` and supplies it through `OPENCODE_CONFIG`. OpenCode merges it with your global configuration; project settings take precedence. Use `--standalone` with the launcher too. See [launcher options](/tools/more-tools#launcher-options).

Rayline recognises the session identifiers OpenCode sends on every request, under the launcher and in manual direct connections alike. The gateway does not forward those session headers; see [conversation grouping through Raydock](/tools/more-tools#the-conversation-id).

## Troubleshooting

- **Another provider or model is used:** check project overrides and the active configuration directory.
- **Authentication fails:** check the key in the process environment and confirm whether the request is direct or going to your gateway.
- **You want your usual setup back:** open a fresh shell without these environment overrides. Your normal configuration has not been replaced.
- See [shared troubleshooting](/tools/more-tools#troubleshooting).

## ARC Dynamic

To use ARC Dynamic, add a model entry named `arc-1.0` alongside the Sage and Swift
entries above, then select it with `--model rayline/arc-1.0`.
For Raydock, include `arc-1.0` in the gateway endpoint’s model list as well.

ARC Dynamic uses the served model’s catalog price rather than a fixed tier
rate; see [ARC Dynamic](/arc/dynamic).
