<span id="verify-both-tiers" />

Use [Unreal Agent](https://github.com/unreallabsai/unreal-agent) with ARC through Raydock and Rayline Platform. Choose **ARC Sage** for challenging coding and agent tasks, or **ARC Swift** as a fast workhorse for everyday tasks.

## Install

Install the official runner:

```bash
brew install unreallabsai/tap/unreal-agent
```

<span id="rayline-local" />

## Raydock

Use Unreal’s **Anthropic provider** with a
[cloud-forwarding gateway](/raydock/connections#configure-a-cloud-forwarding-gateway).
Start that gateway in its own shell with your real Rayline API key. In a
**different shell**, configure Unreal:

```bash
export UNREAL_HARNESS_LLM_PROVIDER=anthropic
export UNREAL_HARNESS_LLM_BASE_URL=http://127.0.0.1:23811/v1
export UNREAL_HARNESS_LLM_API_KEY=local-client
export UNREAL_HARNESS_LLM_MODEL=arc-sage-1.0
```

Use your gateway’s actual port. Unreal’s Anthropic provider expects `/v1` here.
The `local-client` placeholder is for this loopback gateway; only the gateway
process receives the real upstream key. ARC selection and inference run on
Rayline Platform.

Run the agent from a project directory:

```bash
unreal-agent-runner -workspace "$PWD" -p 'Read the README and explain how to run this project.'
```

The runner writes JSONL events to stdout.

## Try another ARC model

To use Swift for an everyday task, select it when starting the runner:

```bash
UNREAL_HARNESS_LLM_MODEL=arc-swift-1.0 unreal-agent-runner \
  -workspace "$PWD" \
  -p 'Read the README and summarize the installation steps.'
```

View the model ARC selected and the request’s cost in [Rayline Usage](/platform/usage).

<span id="direct-api" />

## Direct API availability

Unreal’s `openai` provider sends Responses requests. ARC is [not yet available](/arc/availability) on Rayline Platform’s direct `/v1/responses` endpoint, so use the Anthropic provider and Raydock setup above for ARC.

Use the Anthropic provider with Raydock 0.2.10. Its OpenAI provider can return an empty answer through that gateway version.
